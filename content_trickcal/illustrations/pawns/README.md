# 보드 기물 토큰 v0.2

기존 대표 6종에 기본 말·모노폴리 강아지·증기선·비행기 4종을 추가해 총 10종을 이미지로 표시한다. 미제작 세부 병종·승급 상태·NPC는 코드 도형 폴백을 사용한다.
게임 로직, 이동 규칙, 선택 가능 조건은 바꾸지 않는다.

기존 6종은 흰 배경 원본을 네이티브 이미지 생성 도구로 만든 뒤, 같은 도구로 배경만 제거했다. v0.2의 새 4종은 처음부터 투명 배경으로 각각 독립 생성했다.
생성 원본·투명 결과·프롬프트·SHA-256·알파 영역은 `manifest.json`에 기록한다.
투명 PNG는 재가공하지 않고 복사했다. 흰 체스말의 흰 본체·광택은 불투명하게 보존한다.
흰 배경 PNG는 작업 결과의 `outputs/*_Token_White_v0.1.png`로 보존한다.

## 자동 로드 우선순위

이 폴더를 기준으로 찾으며, 파일이 없으면 경고 없이 다음 경로를 확인한다.

1. 쇼기 승급 시 `<세부 타입>_NARI.png` → `SHOGI_NARI.png`.
2. 세부 타입과 같은 파일: `CHESS_ROOK.png`, `JANGGI_PO.png`, `SHOGI_FU.png` 등.
3. 윷말 별칭 `YUT.png`, 쇼기 공통 별칭 `SHOGI_NORMAL.png`.
4. 계열 대표 파일: `PAWN_CHESS.png`, `PAWN_JANGGI.png`, `PAWN_YUT.png`, `PAWN_MONO.png`, `PAWN_BADUK.png`, `PAWN_SHOGI.png`.
5. 코드 도형. 기본 말은 `PAWN_DEFAULT.png` → 미플 도형.

기본 말 외에는 특정 병종 그림이므로 세부 파일명으로 저장했다. 다른 병종을 잘못 나타내는 공용 그림으로 사용하지 않는다.
공용 계열 PNG를 직접 추가하면 명세대로 폴백에 사용한다. 게임용 PNG는 배경에 실제 알파 투명도가 있어야 한다.
기존 어두운 증강용 대표 그림은 `../augments/pawns/`로 분리했다. 보드에는 사용하지 않는다.
NPC 파일은 `NPC_ROBBER.png`, `NPC_GHOST.png`. 현재는 각각 후드 도적과 청록 고스트 도형.
새 파일은 Godot 임포트 후 로컬에서 표시되고, 웹에는 새 빌드·배포가 필요하다.

## 수치 규격

- 원본: 1:1 정사각형. 정확한 크기는 manifest에 기록. 생성 요청 시 카메라 목표: 정사영, 방위 45°·고도 약 50°. 생성 이미지가 이 각도를 수학적으로 보장하지는 않는다.
- 런타임: 최대 256px, 밉맵. 새 4종은 무손실 압축(mode=0); 기존 6종의 실제 임포트는 손실 압축(mode=1, quality=0.9)이다. 알파 0.08 이상인 영역 + 원본 텍스처 2px 여유로 경계를 측정해 종횡비를 유지한다. 희미한 잔여 알파 픽셀 때문에 본체가 작아지는 것을 방지하며 PNG 자체는 수정하지 않는다.
- 본체 최대 영역: 26×31px. 바닥 접촉 원점 (0, 0), 본체 하단 y=0.
- 받침대: 윗면 반지름 (15,6)px. 측면 y=3, 안쪽 반지름 (11,3.5)px. 지면 그림자 반지름 (16,5.76)px, y=5.
- 소유자: P1 `#E5484D`, P2 `#3E8BFF`, P3 `#30A46C`, P4 `#F5B700`.
- 이미지 외곽 플레이어 색상 확장: 0.7px. 쇼기 승급 외곽: 붉은색 `#FF5E50`, 1.4px. 도형 승급도 같은 붉은 테두리.
- 호기: 플레이어의 말 슬롯 번호 1~4 (`pawn.slot`, 병종 번호 `unit_no`와 별개). 좌측 상단 중심 (-12,-27), 외경 11.4px, 글자 9px. 본체 중앙에는 번호를 쓰지 않는다.
- 업기: 받침대 안쪽 20×9px 배지, `xN` (업은 말 포함 실제 수).
- 남은 필살기: 우측 번개, 1.4초 주기로 알파 0.7~1.0. 사용되거나 완주하면 숨김.
- 클릭·호버 영역: 원점 기준 (-18,-34)부터 36×42px. 현재 이동 연출의 Bounce 좌표계로 검사한다.
- 보드에서는 깊이에 따른 균일 축소만 적용. TILT 접지 보정 2px. 본체만 가로·세로 비율을 달리 누르지 않는다.
- 프로필: 38px 슬롯에서 0.88배 / 48px 슬롯에서 1.12배.
- 프로필·슬롯의 실제 크기가 바뀌면 토큰 위치를 재계산한다. 프로필의 1.05배 턴 강조는 좌석의 화면 모서리를 기준으로 안쪽으로 커지며, 내용이 기준 크기를 넘으면 그 차이만큼 좌석 위치를 보정해 화면 여백을 유지한다.
- 수동 기물 독: 1.28배, y=44. 이동 선택 카드: 0.95배. 진화 대상 카드: 2.05배.

## 미제작 병종 도형

- 기본: 이미지 우선. 파일 누락 시 기존 상아색 미플 도형 폴백.
- 윷말·바둑: 원통/납작한 볼록 돌. 흑·백 재질과 광택 분리.
- 체스: 폰·나이트·비숍·룩·퀸의 서로 다른 실루엣.
- 장기: 팔각 나무 블록 + 포/차/마/상 각인.
- 모노폴리: 미니카·비행기·증기선·강아지 실루엣.
- 쇼기: 오각 쐐기 + 보/비/각/계. 승급 때 붉은 테두리와 승급 글자.
- NPC: 도적은 보라색 받침대·후드·자루, 고스트는 청록 몸체·분홍 외곽·물결 밑면.

보드, 네 모서리 프로필 슬롯, 하단 기물 독, 이동할 말 선택, 진화 대상 선택이 같은 `PawnToken`을 사용한다.

## v0.2 도형 폴백 점검 및 적용

- 기본 말: 사람형 미플 대신 둥근 머리·원뿔 몸체·원형 발의 전통적인 게임말 이미지.
- 모노폴리: 자동차는 기존 MONO_CAR.png가 연결되어 있음을 확인했다. 도형만 있던 강아지·증기선·비행기 3종을 각각 이미지로 추가해 4병종 모두 이미지로 표시한다.
- 자동 로더가 기존 파일명으로 읽으므로 보드·프로필 슬롯·하단 독·이동/진화 선택 화면의 공통 PawnToken 렌더링에 함께 반영된다. 플레이어 색상 받침대·좌상단 슬롯 배지·필살기 번개는 기존 구성을 유지한다.
- 미제작 상태도 확인했다: 체스 폰/비숍/룩/퀸, 장기 포/마/상, 바둑 백돌, 쇼기 비차/각행/계마 및 4종 승급 전용 그림, 도적/고스트 NPC. 이번 변경은 기본 말과 모노폴리 계열을 우선 적용한다.
- 쇼기 보병 승급은 승급 전용 이미지가 없으면 기존 보병 PNG에 붉은 테두리를 표시한다. 다른 쇼기 승급은 도형 폴백이다.
- native image_gen.imagegen 원본은 재가공 없이 복사했다. 생성 모델 ID는 도구에서 공개하지 않는다. 프롬프트·원본 경로·원본/복사본 일치 SHA-256·실루엣 영역은 manifest.json에 기록한다.
- 로컬 검증: Godot 실제 보드 1366 × 768, 모든 병종 갤러리, 기본·모노폴리 5종 실제 크기/2배 비교, 자동 로더의 실제 리소스 경로, UI_MENU_OK를 확인했다. 새 그림은 원본 1254 × 1254 RGBA이며 불투명 본체·알파 여백·플레이어 받침대 노출을 확인했다. 생성 색상의 미세 농도와 안티앨리어싱 때문에 엄격한 3색 인덱스 팔레트는 아니다.
