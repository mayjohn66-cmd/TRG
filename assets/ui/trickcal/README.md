# UI 이미지 시범 스킨 v0.2

사용자가 제공한 트릭컬 리바이브 UI 6장에서 추출한 팔레트와 승인된 팝업 방향을 바탕으로 새로 그린 텍스트 없는 PNG 부품이다. 원작 화면에서 잘라낸 이미지가 아니다.

## 적용 범위

- 법전 바탕·제목 바·빈 슬롯·활성 슬롯·발동 강조
- 판정 도구 패널과 규칙표 바탕
- 공통 사각 버튼의 기본·호버·누름·비활성·포커스 상태
- 인게임 메뉴·선택·결과·연결 종료 팝업의 공통 바탕
- 시작 메뉴·로비의 공통 버튼과 팝업 바탕

보드·타일·기물·플레이어색·카드 삽화·원형 굴리기 버튼·게임 로직은 이번 스킨 범위에 포함하지 않는다. 기존 글꼴 파일과 텍스트 내용도 유지한다. 밝은 패널 위의 문자색은 가독성을 위해 함께 변경했다.

## 출력 규격

- PNG RGBA, 기본 부품 96×64, 작은 버튼용 부품 96×32. 4배 크기로 그린 후 축소해 안티앨리어싱.
- `StyleBoxTexture`의 기본 9분할은 사방 20px. 실제 버튼 높이가 40px 미만이면 작은 버튼 이미지와 사방 14px 분할로 자동 전환한다. 28px 높이의 설정 버튼에서 40px 모서리 영역이 겹치던 문제를 방지한다.
- 텍스트·아이콘은 PNG에 포함하지 않고 기존 Control에서 출력.
- 콘텐츠 여백은 기존 호출부에 맞춰 별도 지정. 슬라이스 폭을 레이아웃 여백으로 사용하지 않는다.
- `skin_spec.json`에 각 이미지의 색상·반경·슬라이스 값을 기록.
- 제목 바는 첫 시범에서 추출 녹색 `#5DA530`을 단색으로 사용한다. 원작 그라데이션을 재현한 것으로 취급하지 않는다.
- 일반/눌림/호버의 콘텐츠 여백은 동일하며 눌림은 아래 음영 제거로 표현한다.
- 버튼의 모든 상태는 같은 본체 윤곽을 사용한다. 기본 크기는 아래 3px, 작은 크기는 아래 2px를 그림자 영역으로 남긴다. 초점 테두리는 그림자 바깥이 아닌 본체 윤곽에 맞춘다.
- 모양을 별도로 덮어쓴 원형 굴리기 버튼 등은 크기별 이미지 자동 전환 대상에서 제외한다.

## v0.2 접합부 보강

로비의 실제 180×28 설정 버튼을 기준으로, 작은 높이에서 모서리와 그림자가 갈라져 보이던 부분을 수정했다. 초점이 있는 상태의 수정 전후를 실제 Godot 렌더링으로 비교했다. 공통 버튼의 기본·호버·누름·비활성·초점 이미지를 같은 윤곽으로 정렬했으며, 글자·클릭 영역·버튼 동작은 유지한다.

[수정 전후 확대 비교](../../../docs/ui-trial/button-border-comparison.png)

웹 검증 중 함께 추가된 연출 속도 설정이 `ui_fx_test.gd`의 이동 대기시간 0초 조건을 덮어써 방아쇠 검사가 실패하는 경우를 확인했다. 메뉴 검사 이후 기존의 즉시 이동 조건을 복원하도록 테스트 준비만 보강했다. 게임의 연출 속도·입력 잠금 로직과 검사 assertion은 변경하지 않았다.

## 재생성

Pillow가 설치된 Python에서 프로젝트 루트 기준:

```sh
python tools/generate_ui_skin.py
```

시각 규격 기준 문서: [규격서](https://github.com/mayjohn66-cmd/TRG/blob/main/docs/visual/Visual_Asset_Guide_Draft.md), [색상 추출 보고서](https://github.com/mayjohn66-cmd/TRG/blob/main/docs/visual/UI_Color_Palette_v0.1.md).

## 검증

Godot 4.7.1에서 import, `ui_menu_test.gd`, `ui_lobby_test.gd`, `ui_smoke.gd` 통과. 최초 스모크 실행에서 425개 행동, 원격 최신 변경을 합친 뒤 격리 재실행에서 796개 행동 후 승리 상태 도달. 1366×768 실제 렌더링으로 메뉴·설정·법전·판정 도구 및 시작 화면을 확인했다.

로컬 Windows 헤드리스 검사에는 인증서 저장소·종료 시 리소스 경고가 있었고, 로비 검사는 네이티브 WebRTC 확장이 없어 관련 오류를 출력했으나 `UI_LOBBY_OK`로 종료했다. 실제 온라인 연결 검증은 이 스킨 검사에 포함하지 않았다.

일부 반복 스모크 실행은 180초 제한을 넘겼으며, 그중 한 실행에서 기존 `tests/ui_smoke.gd:451`의 비행기 스킬 대상 선택이 배열 범위를 넘기는 오류를 확인했다. 해당 테스트는 이번 변경에서 수정하지 않았다. 이후 새 사용자 데이터 폴더에서 실행한 검사는 `UI_SMOKE_OK`로 완료했다.
