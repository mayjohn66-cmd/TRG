# 1.3.1 추가 3D 경량화 — 2026-11-27

기존 42개 파일 모델의 경량본(약 2.64 MB)은 유지한다. 이번 변경은 코드로 만드는 메시와 화면 버퍼의 런타임 부담을 줄인다. 아래 메시 크기는 GPU 실측이나 다운로드 용량이 아니라 정점·인덱스 배열의 바이트 수다. 각 연출 내부 공유 메시는 한 번만 집계하며, 서로 다른 연출 사이 공유 자원은 중복될 수 있다.

| 측정 범위 | 이전 | 이후 |
|---|---:|---:|
| 윷·슬롯·룰렛·마작·야추·운명 코인의 메시 배열 | 1,389,744 bytes | 502,340 bytes |
| 같은 6개 연출의 삼각형 | 16,673 | 7,721 |
| 12개 연출의 메시 배열 합계 | 4,048,472 bytes | 3,147,436 bytes |
| 12개 연출의 활성 3D 렌더 타깃 픽셀 합계 | 6,060,128 | 3,332,278 |

- 윷 단면, 룰렛 외곽과 부채꼴, 슬롯 드럼, 주사위 눈, 마작·슬롯의 둥근 상자, 코인 원통의 분할을 줄였다. 인덱스를 공유해 같은 위치·법선·UV·색의 정점을 재사용한다.
- 코인의 가장자리 24개 돌기는 동일한 BoxMesh를 쓰는 MultiMesh로 묶었다. 앞뒤 문양과 최종 회전·게임 결과는 유지한다.
- 대부분 2배였던 3D 소품 렌더 해상도를 표시 크기의 1.5배로 조정했다. 룰렛 528², 코인 352². 다트·자판기의 4배 MSAA는 2배로 조정했다. 게임 UI 배치 크기, 입력 좌표 변환, 종이·마작 앞면·슬롯 스트립 인쇄 텍스처는 유지한다.
- `web_3d_budget.gd`는 사전 로딩한 3D 뷰포트와 재사용 대기 화면을 32×32로 축소하고 갱신을 멈춘다. 메시·재질은 보관하고, 해당 도구를 실제 사용할 때 원래 활성 크기로 복원한다. 2D 인쇄용 뷰포트는 축소하지 않는다.
- 이 값은 전체 웹게임 메모리 사용량을 보장하지 않는다. 메시 외에도 이미지·음성·브라우저·화면 버퍼가 메모리를 차지한다.

검증: `ui_web_3d_budget_test.gd`는 각 도구의 축소·복원 3회, 인쇄 텍스처 크기 보존, 실제 RollPresenter로 전달 후 복원과 재대기를 검사한다(135 checks). 윷 6종, 슬롯 216조합, 양방향 룰렛 10종, 주사위·마작, 직접 선택 연출·소품 연속성, 다트·자판기·열차 및 기존 42개 경량 모델 구조를 별도 검사한다.

재측정: `tools/art/audit_procedural_3d.gd -- <절대 출력 폴더>`를 Godot `--headless --audio-driver Dummy`로 실행한다. 원본 대비 화면은 `tools/art/preview_procedural_budget.gd -- <절대 PNG 경로>`를 일반 렌더러와 Dummy 오디오로 실행해 확인한다.
