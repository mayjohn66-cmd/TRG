# 핀볼 인게임 3D 연출 v0.1

기존 `PinballStage`의 2D 도형을 이미 제작한 베이스·쇠구슬 native 씬으로 교체했다. 기존 보드의 `발사!` 버튼과 도구 선택 흐름을 그대로 연결한다.

- 스프링 당김 → 오른쪽 레인 상승 → 상단 곡선 레일 → 6개 핀 열 통과 → 결과 포켓 착지 → 포켓 강조 순서다. 기본 강도에서 약 2.8초다.
- 실제 이동값은 `ToolPinball`이 확정한다. 연출은 해당 포켓으로 도착하는 경로만 만들며 게임 RNG를 소비하지 않는다. 자유 물리 시뮬레이션이 아니다.
- `pinball_motion.gd`는 실제 핀 좌표와 구슬 반지름을 기준으로 간섭 없는 경로를 구한다. 일곱 결과 포켓과 네 가지 좌우 패턴을 검사했다.
- 독립된 720×800 투명 SubViewport를 재사용한다. 정지 시 한 프레임만 갱신하고 숨길 때 렌더링과 진행을 중지한다. 초기화·재시작도 대기 중인 연출을 해제한다.
- 고정 메시는 재질별로 합치되, 인덱스 유무가 다른 메시를 먼저 정규화하여 곡선 레일이나 판 면이 누락되지 않게 했다. 스프링·플런저·강조되는 포켓 바닥은 분리했다. native 캡처의 draw calls는 최적화 전 345, 적용 후 47이다.
- 밝은 판에서도 구슬의 금속 하이라이트가 보이도록 별도 환경 반사와 조명을 사용한다. 원본 베이스·구슬 모델 파일은 수정하지 않았다.

## 검증

- 전체 단위 검사: 430 tests / 219041 assertions / 0 failures.
- 기존 UI 통합 검사: `UI_FX_OK`.
- 실제 MainBoard 발사 버튼으로 native Compatibility 실행: `PINBALL_GAME_OK`.
- 결과 포켓·입력 잠금/해제·즉시 모드·뷰포트 재사용·초기화 취소·숨김 취소·게임 RNG 불변·유휴 렌더 중지 확인.
- 7개 포켓 결과와 발사 중 프레임을 실제 렌더링하여 확인했다. 최적화 후 레일의 누락이 없는 것도 확인했다.

리뷰 캡처는 작업공간 `outputs/pinball-ingame-v01/`에 있다. `preview.gif`는 실제 보드 캡처를 잘라 연결한 미리보기다. 이번 단계는 로컬 적용이며 웹 배포나 브라우저 검증은 수행하지 않았다. 종료 시 기존 프로젝트의 리소스 정리 경고는 남아 있다.
