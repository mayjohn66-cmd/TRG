# 카드 계열 판정 연출 v0.1

2026-10-18. 적용 대상은 `HOLDEM`, `DICE_HWATU`, `DICE_TAROT`이다. 확정된 엔진 결과를 개별 카드로 배분·뒤집기·공개하며, 추첨 확률·이동량·추가 턴·상태 변경 규칙은 바꾸지 않는다.

## 화면 규격

기준 캔버스는 1366×768이다. 결과 패널은 기존 보드 중심에 정렬하며 밝은 공통 UI 스킨을 사용한다.

| 항목 | 수치 |
| --- | --- |
| 홀덤 카드 | 96×144px, 5장 |
| 화투 카드 | 104×148px, 현행 규칙 2장 |
| 타로 카드 | 96×156px, 뒷면 5장 중 1장 공개 |
| 카드 간격 | 8px |
| 줄 여백 | 좌우 12px, 위 18px, 아래 12px |
| 프레임 | 배경 `#FFF8E6`, 테두리 2px, 둥근 모서리 9px, 안쪽 여백 3px |
| 테두리 색 | 홀덤 `#8BB35C`, 화투 `#CF7883`, 타로 `#AD8BD5` |
| 그림 | 원본 전체를 비율 유지 표시, 선형 필터 + mipmap |
| 글자 | 기존 ONE 모바일 POP 폰트, 랭크/월 17px, 화투 종류 16px, 타로 번호 16px, 타로 제목 11/14px, 결과 20px |

그림은 카드 프레임과 별도 노드다. 앞면/뒷면을 독립 노드로 두고 한쪽만 표시한다. 뒷면의 둥근 마스크 반경은 텍스처 짧은 변의 7%다. 원본 PNG의 알파나 색상은 편집하지 않는다.

## 연출 수치

| 단계 | 시간/변환 |
| --- | --- |
| 배분 | 0.20초, 남은 비율의 세제곱으로 스택 위치에서 펼침 |
| 배분 회전 | 중앙에서의 카드 순번 차이 × 0.08rad, 종료 시 0 |
| 뒤집기 | 0.22초, X축 배율 `max(abs(cos(πt)), 0.015)` |
| 앞면 전환 | 뒤집기 진행 50% |
| 뒤집기 들림 | `6 × sin(πt)` px |
| 홀덤 카드 공개 간격 | 0.15초 |
| 화투 새 패 공개 간격 | 0.30초 |
| 타로 선택 강조 | 배분 후 0.22초 동안 선택 카드만 8px 위로 이동 |
| 타로 미선택 카드 | RGB 배율 0.85, 불투명 뒷면 유지 |
| 결과 유지 | 모든 공개 종료 후 0.50초 |

정상 결과의 전체 길이는 홀덤 1.52초, 새 화투 2장 1.22초, 타로 1.14초다. 기존에 공개된 화투는 그대로 두고 새 패만 뒤집으므로 공개할 수량에 따라 시간이 줄어든다. 호환용 기존 3장 입력도 처리하지만 현행 엔진은 2장을 뽑는다.

숫자·문양·광/열끗/띠/피는 엔진 카드 ID와 정확히 대응한다. 모든 공개가 끝날 때까지 족보, 이동량, `last_display`를 미리 노출하지 않는다. 0칸은 '이동 없음', 음수는 '후퇴'로 표시한다. 타로 수레바퀴의 추가 굴림과 매달린 남자의 예약 보너스도 실제 결과값으로 표시한다. 타로의 선택 위치는 엔진이 정하며 새 입력/재추첨을 추가하지 않는다.

## 구현 및 검증

- `JudgmentCardArt`: 52장/48장/5운명의 ID와 그림 경로, 포커 문양 배치.
- `JudgmentCard`: 개별 카드 앞뒷면, 이미지와 실제 폰트 표기.
- `RollPresenter`: 배분·순차 공개·결과 표시. D6/친치로의 재사용 3D 뷰포트는 카드 재생 중 렌더링하지 않는다.
- 이미지 24개와 프롬프트/원본 해시는 [그림 manifest](../../assets/ui/trickcal/judgment_cards/manifest.json), 소재 구분은 [그림 설명](../../assets/ui/trickcal/judgment_cards/README.md)에 남긴다.

로컬 Godot 4.7.1에서 단위 테스트 **330개 / 29,089 assertions / 실패 0**을 확인했다. `JUDGMENT_CARD_ART_COVERAGE 52+48+5/105`, `JUDGMENT_CARD_FX_OK`, `UI_FX_OK`를 통과했다. 공개 전 앞면·결과 숨김, 타로 5개 선택 위치 모두에서 정확히 1장 공개, 화투 기존 패 유지, 음수/0칸 표시, 취소 및 3D 뷰포트 휴면을 검사했다.

실제 Godot 게임 화면의 홀덤·화투·타로 애니메이션을 직접 캡처했고, 52장/48장/5종+뒷면 갤러리에서 전체 그림 배치를 확인했다. 캡처에는 검수용 확정 결과를 주입했으며 일반 추첨을 변경하지 않는다. 로컬 Windows headless의 기존 WebRTC 미지원 진단 및 종료 시 자원 경고는 남아 있다. 새 스크립트/셰이더 오류는 없었다. 배포 결과는 해당 소스 커밋의 CI와 Production deployment 상태로 별도 확인한다.
