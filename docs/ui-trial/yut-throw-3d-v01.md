# 네 가락 윷 던지기 v0.1

2026-10-18. `YUT`의 임시 직사각형 네 개를 반원 단면의 나무 윷가락 네 개로 교체했다. 함께 던져 회전하고, 개별 착지·짧은 반동·나무 타격음을 거쳐 확정 결과의 면으로 정착한다. 판정은 기존 엔진이 먼저 정하며 이 연출은 추첨·이동·재굴림 규칙을 바꾸지 않는다.

## 모양과 판정

한 가락은 폭 0.54, 길이 2.30, 높이 0.27의 반원 단면이다. 긴 방향은 로컬 Z이며, 평평한 배의 법선은 로컬 DOWN이다. 양 끝은 0.12 구간에서 폭을 줄여 다듬었다. 표면은 실제 UV가 있는 3D 메시와 별도 셀 명암 재질을 사용한다. 몸체는 변형하지 않고 이동·회전만 한다.

평평한 면에는 굵은 X 각인 네 개가 있고, 네 번째 가락의 배 끝에만 붉은 고리 표식이 있다. 각인과 표식은 정확한 위치·크기의 별도 메시이므로 결과에 따라 생성 그림이 바뀌지 않는다.

| 결과 | 배가 보이는 가락 (0부터) | 배/등 | 이동·재굴림 |
| --- | --- | --- | --- |
| 도 | 0 | 1/3 | 1칸 |
| 개 | 0, 1 | 2/2 | 2칸 |
| 걸 | 0, 1, 2 | 3/1 | 3칸 |
| 윷 | 0, 1, 2, 3 | 4/0 | 4칸, 한 번 더 |
| 모 | 없음 | 0/4 | 5칸, 한 번 더 |
| 빽도 | 표시된 3번만 | 1/3 | 1칸 후퇴 |

기존 `ToolYut.FACES = [-1,1,2,3,4,5]`의 균등 추첨을 유지한다. 던지는 힘으로 앞뒷면 확률을 바꾸지 않는다. 일반 도와 빽도는 배의 개수가 같아도 표시된 가락의 실제 방향으로 구별된다. 형태와 명칭의 참고 자료는 [국립민속박물관 어린이박물관의 윷놀이 설명](https://www.nfm.go.kr/kids/elecontents/view.do?topic=46)이다. 해당 사이트의 그림을 복제하지 않았다.

## 고정 수치

| 항목 | 값 |
| --- | --- |
| 표시 / 렌더 크기 | 500×300px / 1000×600px, MSAA 2× |
| 카메라 | 고정 직교, size 4.5, 위치 (0,8.5,9.6), 목표 (0,0.65,0) |
| 동시 출발 | 0.10초 |
| 각 가락의 비행 | 0.660 / 0.700 / 0.735 / 0.775초 |
| 첫 착지 시각 | 0.760 / 0.800 / 0.835 / 0.875초 |
| 비행 높이 계수 | 파워에 따라 1.00–1.45, `sin(πu)` |
| 회전 | 최종 자세로 slerp + 긴 축 2/3회 회전의 `(1-u)²` 감쇠 + 짧은 축 기울기 |
| 파워 영향 | 비행 높이·회전수만 변경, 최종 자세 동일 |
| 반동·정착 | 첫 착지 후 0.22초, 높이 계수 최대 0.10, 한 번 반동 |
| 국소 카메라 반응 | 각 착지 후 0.07초, 계수 최대 0.016 |
| 결과 공개 / 유지 | 1.12초 / 0.65초 |
| 전체 연출 | 1.77초 |

최종 X는 `[-1.65,-0.55,0.55,1.65]`, Z는 `[-0.15,0.20,-0.15,0.18]`, Y축 각도는 `[-12,5,-7,12]°`다. 정착한 네 가락 사이에는 실제 간격이 있다. 회전하는 반원 단면과 길이에 대한 지지 높이를 계산해 바닥을 관통하지 않게 하며, 모든 결과·최소/최대 파워에서 화면 모서리 여유를 검사했다.

결과 텍스트와 `last_display`는 모두 정착한 뒤에만 공개한다. 빽도는 후퇴, 윷·모는 실제 결과의 재굴림 표시를 사용한다. `Engine.time_scale`, 게임 상태와 네트워크 시계를 변경하지 않는다. 한 뷰포트·공통 몸체·일반/표시 각인 메시를 캐시하고, 종료·취소·도구 전환 시 윷 렌더를 중지한다. 기본 주사위·친치로·마작의 캐시와도 함께 동작한다.

## 그림과 재질

나뭇결 `assets/ui/trickcal/yut/YUT_WOOD.png`는 내장 `image_gen.imagegen`으로 생성한 1254×1254 RGB 원본이다. 그림은 자르거나 색을 수정하지 않고 그대로 보관했다. Godot import에서 무손실·mipmap·512px 상한을 적용한다. 재질은 실제 면 방향의 3단 명암과 밝은 배/갈색 등의 구분을 더한다. 텍스처 반복은 끄며 완벽한 타일링을 가정하지 않는다.

전문·원본 경로·저장 경로·SHA-256·QA는 [manifest.json](../../assets/ui/trickcal/yut/manifest.json)에 기록했다. 생성 1회, 이미지 교정 0회. 이미지 모델 이름은 도구가 공개하지 않는다. 첫 메시 검수에서 발견한 면 방향 문제는 시계방향 앞면으로 수정했고, 나무와 각인의 면 방향 검사를 추가했다. 테두리는 평평한 면과 곡면의 경계에서도 닫힌 윤곽을 유지하는 확대 메시 방식이다.

## 나무 소리

`yut_toss`: 약 0.20초의 짧은 바람 소리, -6dB 보정.

`yut_clack`: 약 83ms의 목재 접촉음. 짧은 1700→950Hz 클릭, 460→235Hz 몸통 공명, 820→590Hz 잔향과 12ms 잡음을 합성한다. 마작의 단단한 패 타격음과 다른 샘플이다. 22,050Hz/16bit PCM을 한 번 생성해 캐시하며 사용자가 같은 이벤트 이름의 파일을 넣으면 기존 로더가 우선 사용한다.

첫 접촉 네 번에 보정 음량 `[-2,-2.5,-3,-3.5]dB`, 피치 `[0.94,0.98,1.02,1.06]`로 재생한다. 0번·2번은 반동이 끝나는 0.980/1.055초에 -11dB의 가벼운 재접촉음이 한 번 더 난다. 무작위 피치는 0이다. 지나간 프레임의 착지음을 뒤늦게 한꺼번에 겹쳐 재생하지 않는다. 기존 효과음 음량·음소거 설정을 따른다.

## 검증

로컬 Godot 4.7.1: **340 tests / 49,664 assertions / 실패 0**, `YUT_FACE_COVERAGE 6/6`, `YUT_THROW_FX_OK`, `UI_FX_OK`. 실제 메시의 바닥 관통, 강체 회전, 회전 중 프레임 여유, 정착 가락의 간격, 여섯 결과·표시 구분, 파워 독립 결과, 접촉 연속성, 시계방향 면, 착지 단일 이벤트, 결과 숨김, 캐시 재사용·취소·D6 복귀를 확인했다.

Native Compatibility 실제 인게임의 개·빽도와 여섯 결과 갤러리를 확인했다. 실제 Movie Writer의 영상·오디오를 함께 기록해 소리 포함 MP4를 만들었다. 녹음은 48kHz 모노로 추출했으며 peak 0.385 미만으로 clipping이 없었다. 실제 3D 뷰포트: **17 draw calls / 4,648 primitives**.

검수 캡처에는 확정 결과를 주입했고 일반 추첨은 유지한다. 기존 Windows headless WebRTC·인증서 진단과 종료 자원 경고는 남아 있으며 새 스크립트·셰이더 오류는 없었다. 로컬 캡처를 최종 배포 브라우저의 직접 시각 확인으로 취급하지 않는다.
