# 친치로 사기주사위 — 면 교체 v0.1

기본 D6의 본체·카메라·명암·그림자·굴림·착지·1.0초+0.35초 재생을 공유한다. 친치로는 눈금 메시만 교체한다.

- 실제 게임 데이터 `ToolChinchiro.FACES` = `[4,4,5,5,6,-6]`을 그대로 사용한다. 4와 5는 각 두 면이며 추첨·확률·후퇴 규칙은 변경하지 않았다.
- -6 면은 여섯 개의 붉은 눈금과 넓은 마이너스 표식으로 구별한다. 마이너스는 면 위쪽 y=0.605~0.675, x=-0.18~0.18의 칠이며 추가 눈금이 아니다.
- 양수 면은 기존 녹색 눈금. 6과 -6은 서로 다른 물리적 면이다.
- 판정값을 물리적 면 번호로 변환한 후 기존 정지 자세를 사용한다. 음수 결과를 일반 D6의 1면으로 clamp하지 않는다. 중복된 양수 결과는 첫 번째 일치 면에 정지하며 두 중복 면의 실제 칠은 각각 존재한다.
- 같은 뷰포트·본체·재질을 재사용하며 D6/친치로별 눈금 메시를 캐시한다. 다시 D6를 굴리면 원래 1~6 칠로 복원한다.
- 삐끗 결과는 `삐끗! 6칸 후퇴`와 붉은 글씨로 표시한다. 기존 결과 공개·후퇴 처리는 유지한다.
- 실제 렌더의 친치로 뷰포트: 4 draw calls / 6748 primitives.

## 검증

전체 327 tests / 28498 assertions / 0 failures 및 `UI_FX_OK`. 여섯 물리적 면의 실제 값·눈금 수, 모든 고유 결과 4/5/6/-6의 정지 면, 6과 -6의 구별을 검사했다. 실제 UI 검사는 결과 일치·같은 뷰포트 재사용·눈금 메시 교체·D6 복원·렌더 중지를 확인한다.

공유 연출 시간은 기존 D6 사례로 실시간 측정한다. 신규 네 결과는 완료 시각을 직접 진행시켜 검사한다. 네 번을 실시간 재생하며 다른 테스트의 턴 제한시간까지 진행되던 첫 검사에서는 후속 턴 알림 전제가 실패했으며, 기존 알림 assertion을 유지한 채 신규 사례를 시간에 독립적으로 바꾸어 통과했다.

Native Compatibility에서 여섯 면과 실제 인게임 -6 굴림 39프레임을 확인했다. 신규 스크립트·셰이더 오류 없음. 기존 Windows 인증서·WebRTC 진단 및 종료 시 자원 경고는 별도다. 로컬 캡처를 최종 배포 브라우저의 직접 확인으로 취급하지 않는다.
