# Black-stone alkkagi on the actual board

The one-use black Go stone skill temporarily unfolds the existing diamond board into an overhead view. The same board artwork, tiles, traps and actual pawn sprites stay on screen. There is no separate wooden board or replacement set of black/white stones. The camera returns to its previous view after cancellation or settlement without changing the saved view preference.

Press the actual black stone to show a directional arrow immediately. Drag backward to aim in the opposite direction: a slim shaft made of progressively larger yellow-to-orange slats leads into the arrowhead. Increasing power lengthens the arrow and deepens the head toward red. The pull tether and dotted continuation to the predicted endpoint reinforce direction and strength without numerical power labels. Release starts the slide and dry clack immediately, without another windup or blocking skill announcement. Pressing elsewhere, tiny drags, Escape, right click, the cancel button, cancelled OS touch, focus loss and resize never consume the skill.

The real black-stone sprite slides quickly and decelerates. Authoritative victims receive a spatially ordered contact, a small spark, a dry impact sound and a 65 ms local hold. Their actual pawn sprites then tumble upward and outward off the board. The shooter settles onto its resolved tile before the camera returns and subsequent landing effects resume. Generic capture cutins and duplicate ejections are suppressed only for these already animated victims; unrelated landing captures still use the normal queue.

AlkkagiStage owns gesture feedback and local presentation time. MainBoard projects its overlay onto the board and animates the existing pawn views. PawnSkills.shot_result remains authoritative for power, direction, vulnerable enemies, immunity, landing and one-use consumption. This presentation adds no new rebound, random result or chain-capture rule and never changes Engine.time_scale. Remote and bot skill events use the same event path.

tests/ui_alkkagi_test.gd checks stone-only selection, immediate direction feedback, mouse and touch release, cancelled touch, tiny drags, coordinate direction, preview/engine agreement, allied and shielded exclusions, ordered contacts, local hit-stop, deceleration, missed shots, actual opponent sprite movement, camera restoration, queue completion and reset. Native 1366x768 and 844x390 captures and a recorded demo are in workspace outputs/alkkagi-board-v02. CI runs this focused test alongside the existing UI smoke and full UI FX suites.
