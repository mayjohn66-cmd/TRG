# 모바일 연출 좌표 — 2026-10-27

가로 844×390과 740×360에서, 효과가 떠 있는 동안 폭을 바꾸는 경우까지 포함해 연출 위치를 점검했다. 배포와 같은 1366×768 canvas-items/expand 늘이기를 쓴다. 844×390은 논리 화면 1662×768과 보드 가로 오프셋 148px이 된다. 시뮬레이션·입력·결과·난수·전체 시간 배율은 바꾸지 않았다.

점검은 실제 보드를 만들기 전에 `MobileSupport.force_touch`를 켜서, 데스크톱 테스트 환경에서도 터치 기기용 글자·버튼 배치를 포함한다.

`tests/ui_mobile_fx_test.gd`가 실제 OpenGL과 헤드리스 둘 다에서 좌표 측정 72건을 통과했다. 고친 뒤 최대 오차는 0.000109 화면 픽셀(부동소수점 잡음)이고 기준은 1.1 화면 픽셀이다. 난수 상태와 전체 시간 배율이 바뀌지 않는지도 확인한다. 함께 맞춘 연출: 지뢰 칸, 저격수 초점, 공통 압박 고리, 프로필 오라, 스포트라이트, 기차 레일 투영, 니트로 말·불꽃·빛, 결투 6종 틀. 남에게 가는 카드는 뒷면을 유지한다.

실제 모바일 렌더로 말 붙음, 장면 틀, 스포트라이트 범위, 레일, 니트로, 발사 뒤 크기가 바뀐 BANG! 무대를 확인했다. 기존 검사 6종(`castling`, `bakery`, `bond`, `bang`, `gambler`, `raid`)도 원래 발동·완료 검사를 통과했다. CI 범위 `mobile-fx`는 내보내기·배포 전에 모바일 좌표 점검과 이 6종만 돌리며, 게임 전체 테스트는 이 요청 범위 밖이다.

배포된 웹 캔버스는 브라우저로 844×390, DPR 2에서 확인했다: CSS 경계 0,0,844,390, 백버퍼 1688×780. 브라우저 화면 캡처가 시간 초과되어 시각 검수는 같은 모바일 화면 크기에서 실제 제작 렌더로 했다. 화면 크기 테스트이며 실제 기기에서 플레이한 테스트는 아니다. 새 그림은 넣지 않았다.
