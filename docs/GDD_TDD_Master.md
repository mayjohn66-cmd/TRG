## 1. 프로젝트 개요 (Project Overview)

- **타이틀:** 초증강 엘리아스 마블 (Hyper Augment Elias Marble) — 초기 가제 `에르핀의 억지 레이스: 보드게임 대격돌`에서 최종 확정
- **장르:** 2~4인 멀티플레이(사람 간 대결, AI 혼합, 또는 1인 vs AI 3명) 비대칭 카오스 보드 레이스 (*트릭컬 리바이브* 비공식·비영리 2차 창작 팬게임)
- **엔진 및 플랫폼:** Godot Engine 4.7 / GDScript 2.0 (웹 브라우저 HTML5 가로 화면 기본, Windows PC 클라이언트 동시 지원)
- **핵심 플레이 타임:** 판당 10~15분 내외
- **배경 및 핵심 컨셉:** 교주가 주말에 즐기려고 모아 둔 전 세계 보드게임(윷놀이, 체스, 장기, 부르마블, 바둑, 쇼기, 우노, 뱅, 포커, 마작, 유희왕 등) 상자를 에르핀과 사도들이 한꺼번에 엎어 버린 뒤, 제멋대로 도구와 규칙을 섞어 완주 내기를 벌이는 대환장 멀티버스 파티.
- **핵심 가치 (Core Values):**
  1. **아바타와 기물의 역할 분리:** 트릭컬 사도 아바타는 화면 모서리에서 감정 표현·상황별 보이스·처치 및 승리 컷신만 담당하고, 실제 보드판 위에서는 정통 보드게임·아케이드·TRPG·수집품 기물들이 뛰어다닌다.
  2. **서바이벌 순위제와 특수 승리 경쟁:** 내 말 4개를 모두 완주시키거나 공용 법전(슬롯 최대 4칸, 동시 활성 기본 2개)에 올라온 특수 승리 교칙을 먼저 달성한 순서대로 1위 → 2위 → 3위로 졸업한다.
  3. **4대 카오스 카드 체계 (방어·발동·함정·소환):** 피격 순간 팝업으로 받아치는 방어 카드, 판세를 뒤집는 발동 개입, 뒷면으로 숨겨 까는 일반 함정과 코너 전용 함정, 라운드마다 트랙을 휩쓰는 중립 기물 소환으로 예측 불가능한 변수를 만든다.
  4. **규칙 코어와 화면을 분리한 아키텍처:** UI 종속성이 없는 순수 규칙 엔진(`core_engine/`), 커맨드 스택(되감기·개입), 시드 고정 결정론적 락스텝(WebRTC P2P), CSV 데이터 주도 밸런스 테이블로 설계했다.
  5. **단순한 승리 목표 + 개별 기물의 개성:** 복잡한 세트 시너지를 없애고, 기물 하나하나의 상시 능력과 1회용 필살기, 21종의 판정 도구, 주기적인 증강 드래프트에서 매 판 다른 조합의 재미가 나오도록 했다.
  6. **직관적인 미니멀 HUD:** 긴 설명 문장 대신 아이콘·스포트라이트·불꽃·도장으로 상태를 전달하고, 모든 자동 발동·이동·처치 연출은 단일 FIFO 연출 대기열을 통해 한 사건씩 순서대로 보여 준다 (4.5절 참고).

## 2. 기술 아키텍처

### 2.1. 설계 원칙

1. **규칙 코어와 화면 분리:** `core_engine/`은 UI 노드를 전혀 참조하지 않는 순수 규칙 계층이다. 모든 행동은 `TurnManager.act()`로만 들어오고 결과는 시그널·이벤트로 나간다. 화면(`scenes/`)은 그 결과를 받아 순서대로 그리기만 한다. 덕분에 사람·봇·온라인 상대가 동일한 검증 경로로 행동하며, 헤드리스 테스트만으로 규칙 전체를 빠르게 검증할 수 있다.
2. **코어와 스킨 분리 (데이터 주도):** 2차 창작 리소스(`content_trickcal/`)와 밸런스·번역 수치 표(`content_trickcal/data/*.csv`)를 코드와 분리한다. 보드 구성 역시 `BoardCatalog` 데이터 테이블로 정의한다.
3. **커맨드 스택과 스냅샷:** 카드·필살기 같은 행동은 `GameCommand`로 감싸 `CommandStack`에 기록하고, 턴 전체 되감기(`바이츠 더 더스트`)는 턴 시작 시점의 `TurnSnapshot`으로 상태를 복원한다.
4. **엔티티와 칸 설치물:** 플레이어 말(`PlayerPawn`)과 중립 기물(`NeutralNPC`)은 `BoardEntity`를 상속하고, 함정·호텔 같은 타일 위 오브젝트는 `TileAttachment`로 부착한다.
5. **결정성 (Determinism):** 판 진행에 쓰이는 모든 무작위는 `GameState.rng` 단일 인스턴스에서만 뽑는다. 시드와 행동 순서가 같으면 언제나 동일한 판이 재현되므로 온라인 락스텝 동기화와 되감기가 성립한다. 화면 연출은 게임 난수를 소비하지 않는다.

### 2.3. 온라인 동기화 (락스텝)

1. 모든 참가자가 **동일한 초기 시드**로 각자의 `TurnManager` 인스턴스를 구동한다.
2. 방장(호스트)이 모든 행동(사람 입력·봇 행동·제한 시간 만료)에 일련번호를 매겨 브로드캐스트하면, 전원이 같은 순서로 `act()`를 실행한다 (`NetGame`).
3. 매 행동 뒤 상태 지문(`state_hash`)을 대조해 동기화 어긋남(Desync)을 즉시 감지한다.
4. 방 규칙(보드·법전 상한·제한 시간 배율·함정 공개 여부·카드/증강 밴 등, `GameSession.RULE_KEYS`)은 게임 시작 전에 방장이 확정해 전원에게 전달한다. 모든 참가자는 같은 빌드·같은 CSV 데이터를 사용해야 한다.

## 3. 인게임 보드(32칸 사각 순환 트랙)와 턴 상태 머신

### 3.1. 순환 트랙과 칸 번호 (`BoardSpec`)

가운데가 비어 있는 **32칸 사각 외곽 트랙**(한 변 8칸)이다. 0번(우측 하단 출발선)에서 출발해 반시계 방향으로 한 바퀴를 돌아 0번을 밟거나 지나치면 완주한다. 모든 칸 번호는 `BoardSpec` 한곳에서 정의하며 규칙·화면·도감이 이를 공통 참조한다 *(단위 테스트는 `BoardSpec.apply(24)`로 구 24칸 배치도 호환 검증한다)*.

| 칸 종류 | 칸 번호 | 규칙 |
|---|---|---|
| 출발·결승 | `0` | 0번을 밟거나 넘으면 즉시 완주 (이동 눈금이 남아도 완주). 범용 증강(`슬슬 지루한데...`)으로 결승선이 당겨진 경우 해당 구간(`TempoUp.in_zone_for`)에 진입해도 완주 |
| 코너 | `8` · `16` · `24` | 코너 전용 함정 설치 칸 및 일부 기물 능력의 코너 판정 칸(`bonus_corner_tiles`). **16번은 반환점** |
| 반환점 이후 | `16` ~ `31` | 체스 폰의 퀸 승진 및 쇼기 기물의 나리 승급 구간 (`promotion_tiles`) |
| 상점·정령 자리 | `5` · `13` · `19` · `30` | 보드에 따라 빵집·편의점·마녀 상점·정령 칸으로 동작 (4.0절 참고) |
| 옷장·장치 자리 | `12` · `22` | 에르핀 왕국에서는 옷장 포탈: **정확히 멈췄을 때만** `12 ↔ 22` 순간이동 (`모노:비행기`는 `12 → 24`, `22 → 30`). 다른 보드에서는 자판기·마녀의 가마솥·정령 칸으로 동작하며 워프하지 않음 |
| 부스터 발판 | `3` · `27` | 굴림 이동으로 정확히 멈추면 앞으로 `+3칸` 추가 전진 (`augments_table.csv`의 `RULE_DASH_PAD`) |

- **설치물 규칙:** 한 칸에는 설치물 하나만 놓을 수 있다. 일반 함정은 코너·특수 칸을 피한 일반 칸에, 코너 함정은 코너(`8·16·24`)에만 설치한다. 출발선(`0`)에는 어떤 설치물도 놓을 수 없다. 은신 함정은 상대 화면에 뒷면(`?`)으로만 보인다(방 규칙에서 함정 공개를 켜면 모두 공개).
- **후퇴 눈금 없음:** 판정 도구는 음수 눈금을 내지 않으며, 실패 결과는 `0칸 이동 + 턴 종료`다. 말이 뒤로 이동하는 경우는 정령산의 불 정령, 벨라티엔의 폭발 물약, `방해령 베루`처럼 명시된 특수 효과뿐이다.
- **중앙 오픈 스테이지:** 트랙 안쪽에는 타일이 없으며 굴리기 버튼, 3D 판정 도구 연출, 일기토 결투장, 중앙 이벤트 알림 카드가 펼쳐지는 무대로 쓰인다.

### 3.2. 턴 상태 머신 (`TurnManager`, `GameEnums.Phase`)

| 단계 (`Phase`) | 수행 내용 | 기본 제한 시간 (초) |
|---|---|---|
| `ROUND_START` | 증강 라운드(4라운드부터 3라운드 주기: `4·7·10·13…`)일 때 전원 동시 3지선다 드래프트 → 선택한 증강 공개·확인 | `15` + 확인 `4` |

#### 공용 규칙 (업기·잡기)

- **업기:** 출발선을 제외한 칸에서 아군 말이 있는 칸에 도착하면 합류 여부를 묻고, 합류 시 하나의 스택으로 묶여 함께 이동한다. 또한 이동이 끝난 칸 바로 앞·뒤 1칸 안에 다른 내 말이 있으면 한 칸 당겨 자동으로 합류한다(업기 자석, 개발 기록 6.96·6.98).
- **잡기:** 적 말이 서 있는 칸에 멈추면 그 말(업혀 있던 말 전원 포함)을 장외 홈런으로 출발선에 되돌리고, 사출된 말에게는 다음 출발 시 발동하는 🔥 **리벤지 부스터**를 부여한다. 백돌 방어막·보호막·방어 카드가 이를 막을 수 있으며, 같은 칸에 업히지 않고 따로 서 있는 말들은 개별 판정한다.

#### 1.3.1 판정 도구 조작·연출 (결과·확률은 그대로)

결과는 굴릴 때 엔진이 정하고, 내 화면에서 내가 굴린 것만 손으로 다룬다 (컴퓨터·온라인 상대·시간 초과는 자동, 오래 두면 저절로 진행). 자세한 연출 순서는 [`DEV_HISTORY.md`](DEV_HISTORY.md) 7.105~7.136.
- **던지는 도구 (기본 주사위·친치로·윷):** 굴리기 버튼 위 판 한가운데 놓인 소품(`ToolRestProp`)이 그 자리에서 튀어 오르며 구르고, 착지 후 잠깐 뜸을 들였다가 결과를 보여 준다. 굴리기 버튼(스페이스)을 꾹 누르면 파워 게이지(주사위·윷·친치로·야추·핀볼)가 왕복하며 던지는 세기만 정한다.
- **꺼내기 도구:** 던지지 않는 도구는 버튼이 [꺼내기]이고 판 위에 미리 놓여 있지 않다가 위에서 쿵 떨어진다. 다트·인생게임 룰렛·러시안 룰렛·해적 룰렛은 꺼낸 뒤 직접 다룬다 (다트 = 과녁 판만 도는 과녁을 눌러 던짐, 해적 = 통을 끌어 돌리고 구멍을 눌러 칼을 꽂음). 슬롯은 놓인 뒤 릴이 돌고 레버를 당길 때마다 하나씩 멈춘다. 주식 차트는 태블릿을 아래에서 꺼내 들고 화면이 켜진 뒤 시작한다. 캡슐뽑기는 놓이고 잠깐 뒤 레버 쪽으로 다가가 동전이 들어간 다음 레버를 돌린다.
- **카드 시점:** 타로·화투·홀덤·스크래치 복권·리치 마작·블랙잭·야추·핀볼은 판 가운데로 다가가(알까기 시점 확대) 전용 매트·케이스 위에서 쓴다. 고르기 창(`ToolPickModal`): 타로 5장 중 1, 화투 3장 중 2. 홀덤은 5장을 받고 한 번 교환(`HoldemExchangePanel`). 마작은 뒷면 패 13개 중 3개를 꺼낸다(`ToolHandGate`). 야추는 펠트 케이스의 컵에서 굴리고 고정한 주사위는 위 칸으로. 핀볼은 핀볼대를 판 위에 내려놓고 쏜다. 스크래치 복권은 나무 계산대를 들고 와 놓은 뒤 손가락으로 긁는다.
- **카드 효과로 얻는 카드:** 기물 패시브(강아지·미니카·비행기·청소기)로 얻는 카드는 그 말에서 날아온다.
- **도구 연출 완결 전 후속 연출 침범 금지:** 모든 판정 도구(향후 추가되는 도구 포함)는 `등장·꺼내기 → 직접 조작 → 결과 공개 여운 → 소품·매트·계산대 수거 및 기본 보드 시점 복귀`까지 전 구간이 완전히 끝난 뒤에야 말 선택·말 이동·이동 실패 배너·다음 차례 전환으로 넘어간다. 앞선 플레이어의 도구 연출이 정리되기 전에 다음 플레이어(봇 포함)의 대기 소품·굴리기 버튼·알림 카드가 먼저 뜨거나 겹쳐 침범해서는 안 된다.

#### 주요 판정 도구 세부 규칙

- **야추·블랙잭·핀볼 (중앙 스테이지 조작):** 세 도구는 중앙 오픈 스테이지(`scenes/stage_yacht.gd`, `stage_blackjack.gd`, `stage_pinball.gd`)에서 직접 조작한다.
  - **야추:** 첫 굴림에 주사위 5개를 굴린 뒤 최대 2회까지 원하는 주사위를 `[고정]`(`keep` 5개 bool, `ToolYacht.set_keep`)하고 나머지를 리롤한다. `stop`(`cash_out`) 또는 리롤 소진/시간 만료 시 현재 족보로 확정된다. 봇은 가장 많이 겹친 눈금(동률 시 높은 눈금)을 고정하며 7칸 이상 족보 달성 또는 리롤 소진까지 굴린다.
  - **블랙잭:** 첫 `roll`에서 카드를 받되 합계가 11 미만이면 11 이상이 될 때까지 자동 추가 드로우한다. 이후 `roll`=히트, `stop`=스탠드이며, 정확히 21이면 즉시 확정(`11칸 + 한 번 더`), 22 이상이면 `[BUST! (21 초과 - 0칸 이동 실패)]` 연출 후 턴이 넘어간다. 봇은 16 이하 히트·17 이상 스탠드다.
  - **핀볼:** 한 번의 `roll`로 목표 구멍이 호스트 RNG에서 결정되며, 발사 스프링 게이지(`_pending_power`)는 순수 궤적 연출 속도만 조절한다.
- **화투 패 (섯다 족보):** 1~12월 각 4장 구성(광은 1·3·8·11·12월 첫 패). 두 패 월 합 끝자리로 끗을 계산(`1~3끗` 2칸 / `4~6끗` 3칸 / `7~9끗` 4칸 / `0끗` 망통 0칸·턴 종료)하며, 같은 월 두 장은 땡(`1~4땡` 6칸 / `5~9땡` 7칸 / `장땡` 8칸), 광 두 장은 `광땡`(8칸)이다 *(초기 고/스톱·피박 규칙은 직관성을 위해 제거)*.
- **마작·타로:** 마작은 결과 등급을 확률(역만 8% · 커쯔 10% · 슌쯔 22% · 또이츠 25% · 핑후 35%)로 먼저 정한 뒤 그에 맞는 패 3장을 구성한다. 타로의 `매달린 남자`가 남긴 `+8칸` 축복은 다음번 이 도구로 굴릴 때 1회 합산된 뒤 소멸한다.
- **해적 룰렛·스크래치 복권 (1.3 신규):** 해적 룰렛(`PirateBarrelView`)은 8구멍 중 1개의 당첨 구멍을 피해 칼을 꽂을 때마다 `+2칸`씩 누적(최대 7자루 14칸 자동 확정)하며, 봇은 칼 3~4개에서 멈춘다. 스크래치 복권(`ScratchTicketView`)은 은박 셰이더로 3칸을 긁어 당첨 문양 일치 수로 칸수를 정하며, 일치한 칸에 황금 문양이 있으면 최종 칸수가 2배(최대 24칸)가 된다 (`tests/test_new_tools_v14.gd`).

  - 우측 상단 바: 언어 전환 · 공지사항(아코디언 목록, 새 글 `N` 배지) · 규칙 도감 · 설정
- **놀이터 설정 화면:** 좌측에서 보드판 선택(미리보기 이미지 + 한 줄 요약), 우측에서 AI 난이도(불닭 매운맛 지표 **Fire Level 1~5단계**)를 고른 뒤 `[게임 시작]`.
- **온라인 대기방:** 4인 좌석을 캐릭터 자리 카드 4장(좌석 색상 테두리·P번호·방장 왕관·아바타·닉네임·`[AI 봇으로 채우기]`/`[내보내기]`/`[비우기]`)으로 표시한다. 방장은 방 규칙 창에서 보드·법전 상한·제한 시간 속도·함정 공개·봇 난이도·카드/증강 밴을 설정한다 (`ui_menu_test`, `ui_lobby_test`).

### 4.4-c. 규칙 도감 (1.2.1 재구성 · 현행)

| **상단 중앙** | 증강 타임라인(현재 + 앞 5라운드 칩, 증강 라운드 표시 및 다음 증강 사전 예고), 그 아래 핵심 사건 자막(처치·사출·법전·순위 확정) |

| **우측** | 내 판정 도구 카드(도구명·전체 족보/눈금 규칙표·전진 칸 범위) |

- **단일 연출 대기열 및 연출 침범 금지 원칙 (필수 불변식):**
  - 엔진이 결과를 먼저 확정한 뒤, 화면은 단일 FIFO 연출 큐를 통해 `오프닝/라운드/차례 배너 → 카드·필살기 발동 → 판정 도구 연출(소품 수거·시점 복귀 포함) → 말 이동·워프 → 함정·처치 컷인·장외 사출 → 법전·순위 확정 → 다음 차례` 순으로 한 사건씩 재생한다.
  - **앞선 연출이 퇴장·정리 모션까지 완전히 끝나기 전에는 어떤 후속 연출·배너·모달·다음 차례(봇 행동 포함)도 화면에 끼어들거나 겹쳐 침범할 수 없다.**
  - 전면 연출·모달(증강 드래프트, 방어 개입 팝업, 결투장, 판정 도구 직접 조작 스테이지/매트, 대상 선택 창, 결과 화면 등)이 열려 있는 동안에는 하위 HUD 위젯(굴리기/꺼내기 버튼, 대기 소품, 보드 타일 툴팁, 비차단 보조 창)을 숨기거나 잠가 화면 겹침을 원천 차단한다.
- **모바일·터치 대응 (`MobileSupport`):** 터치 기기에서는 주요 버튼 최소 높이 `48px`·작은 글씨 `1.2배`·버튼 주변 `26px` 터치 보정을 적용하고, 스크롤 영역 어디든 끌어서 스크롤, 알까기·컬링은 화면 아무 곳이나 잡고 당겨 조준하도록 지원한다. 세로 화면 접속 시 가로 회전 안내를 띄운다.
- **설정 및 다국어 (`L10n`):** 전체화면, 화면 흔들림, 배터리 절약(30fps), 음량(효과음·배경음·캐릭터 보이스), 저화질 모드(터치 기기 기본), 언어(`한국어` / `English` / `日本語`) 실시간 전환을 지원하며 `tests/ui_overlap_audit.gd`로 다국어 텍스트 넘침을 상시 검증한다.

### 4.6. 자동 발동 알림과 AI 대전 모드

- **중앙 이벤트 알림 (`EventAnnouncer`):** 법전 제정·카드 발동(`[P2 발동!]` + 카드 앞면)·함정 작동·증강 공개·중립 기물 이동·퀸 승급·필살기·이동 실패 등 주요 사건을 중앙 카드로 1~2.6초간 순서대로 보여 준다. 알림이 떠 있는 동안 입력과 봇 행동이 잠기며 클릭 시 즉시 넘길 수 있다.
- **AI 대전 모드 (`BotController` · `BotBrain` · `BotTemper`):** 놀이터에서는 불닭 매운맛 지표 **Fire Level 1~5단계**(Lv.1 크림 자비 모드 ~ Lv.5 핵불닭 플레이어 집중 견제 모드)를 선택할 수 있다. AI는 사람과 동일한 `TurnManager.act()` 검증을 거쳐 증강 선택, 말 선택, 카드·함정·방어 카드 개입, 다단계 판정 도구 스톱 타이밍, 1회용 필살기 조준까지 수행한다. AI 턴은 **터보 연출**로 빠르게 넘어가며, 사람 말이 잡히거나 특수 승리가 변동되는 턴만 일반 속도로 전환해 주목시킨다.
