# **📑 \[마스터 기획서 & 기술 설계서 v3.0\] 초증강 엘리아스 마블 (Hyper Augment Elias Marble)**

> **v3.0 (2026-10-16, 구현 기준 전면 개정):** 이 문서는 실제 코드(`core_engine/`, `scenes/`, `tests/`)와 대조해 현행화했다. 기물 세트 효과는 삭제되고 6대 기물 계열 + 1회용 필살기 체제이며, 판정 도구 10종·생떼 카드 16종, 네 모서리 좌석, 5자리 방 코드 온라인 대전(락스텝)과 빠른 랜덤 매칭, 웹 배포(Vercel)까지 반영했다. 세부 예외 규칙은 `EDGE_CASE_SPEC.md`, 개발 이력은 6절에 있다.

## **1. 프로젝트 개요 (Project Overview)**

-   **타이틀:** 초증강 엘리아스 마블 (Hyper Augment Elias Marble) — 기존 가제 `에르핀의 억지 레이스: 보드게임 대격돌`에서 최종 확정

-   **장르:** 2~4인 멀티플레이(사람끼리 또는 AI 혼합, 혼자서는 AI 3명과 대결) 비대칭 카오스 보드 레이스 (트릭컬 리바이브
    > 2차 창작 팬게임)

-   **엔진 및 플랫폼:** Godot Engine 4.7 / GDScript 2.0 (웹 브라우저 HTML5 가로 화면 전용, Windows PC 클라이언트 동시 빌드)

-   **핵심 플레이 타임:** 판당 10 \~ 15분 내외

-   **배경 및 핵심 컨셉:\
    > **교주가 주말에 하려고 모아둔 전 세계 보드게임(윷놀이, 체스, 장기,
    > 부르마블, 바둑, 우노, 뱅, 포커, 카탄, 유희왕 등) 상자를 에르핀과
    > 사도들이 한꺼번에 엎어버린 뒤, 자기 멋대로 도구와 룰을 섞어서 완주
    > 내기를 하는 대환장 멀티버스 파티.

-   **핵심 가치 (Core Value):**

    1.  **아바타와 기물의 역할 분리:** 트릭컬 사도는 화면 모서리에서
        > 감정표현·볼따구 당기기·생떼 컷신만 담당하고, 실제 보드판
        > 위에서는 근본 보드게임 기물(윷말, 체스 나이트, 장기 포 등)들이
        > 뛰어다님.

    2.  **실시간 입법 전쟁 (FIFO 4슬롯):** 플레이어들이 직접 공용 법전에
        > 패시브 교칙을 추가하고 기존 교칙을 밀어내며 판도를 뒤흔듦.

    3.  **3대 카오스 액티브 (즉발·함정·소환):** 우노 리버스 같은 즉발
        > 개입, 유희왕식 뒷면 타일 함정 설치, 카탄의 도적 같은 배회형
        > 중립 NPC 소환으로 예측 불가능한 변수 창출.

    4.  **포트폴리오 특화 아키텍처:** 인터셉터 파이프라인(OCP), 커맨드
        > 스택(Undo/Interrupt), 방향성 그래프 및 엔티티 컴포넌트 분리를
        > 통한 상용 수준 설계.

    5.  **단순한 규칙 + 기물 개성:** 세트 시너지·세트 특수 승리는 없다.
        > 승리는 \[내 말 4개 완주\] 하나뿐이고, 재미는 기물 하나하나의
        > 상시 능력과 1회용 필살기, 그리고 법전·생떼 카드에서 나온다.

    6.  **미니멀 HUD:** 글씨 대신 아이콘과 명암(스포트라이트)으로 상태를
        > 전달하고, 자동으로 일어나는 일은 화면 중앙 알림으로 직접
        > 보여 준다 (4.5 참고).

## **2. 기술 아키텍처 및 디자인 패턴 명세 (TDD & Architecture)**

### **2.1. 소프트웨어 공학 설계 4대 원칙**

1.  **개방-폐쇄 원칙 (OCP - Interceptor Pattern):** 새로운 교칙이나 함정
    > 카드가 100장 추가되어도 TurnManager와 BoardGraph의 코드는 수정되지
    > 않는다.

2.  **코어와 스킨의 완전 분리 (MVC & Data-Driven):** 2차 창작
    > 리소스(content_trickcal)와 순수 보드게임 프레임워크(core_engine)를
    > 분리하여 언제든 오리지널 IP 상용 게임으로 전환 가능하게 설계한다.

3.  **커맨드 스택 기반 개입 및 롤백 (Command Stack Pattern):** 모든
    > 행동과 생떼 카드를 GameCommand 객체로 캡슐화하여 LIFO 역순 판정 및
    > 시간 역행(undo)을 완벽히 처리한다.

4.  **엔티티 및 타일 데코레이터 확장성:** 플레이어 기물(PlayerPawn)과
    > 중립 소환수(NeutralNPC)를 단일 BoardEntity로 추상화하고, 타일 위
    > 은신 함정을 TileAttachment 컴포넌트로 모듈화한다.

### **2.2. 전체 클래스 구조도 (Architecture Tree)**

-   **TurnManager (턴 & 상태 총괄 매니저)**

    -   역할: 현재 턴 상태(8단계 FSM), 진행 방향(우노 리버스 대응), 개입
        > 스택(CommandStack) 관리

    -   주요 함수: change_state(), reverse_turn_order(),
        > request_action()

    -   **\[연결 1\] RuleBookManager (중앙 법전 4슬롯 큐)\
        > **

        -   LawResource: 패시브 교칙 최대 4개 보관 (FIFO 밀어내기 구조)

        -   RuleContext: 주사위 눈금, 이동 경로 데이터를 통과시키며
            > 수치를 변조하는 페이로드 객체

    -   **\[연결 2\] GameCommand & CommandStack (개입 및 롤백 스택)\
        > **

        -   역할: 3.5초 개입 타이밍 동안 들어온 생떼 카드를
            > LIFO(후입선출)로 실행 및 취소(undo)

    -   **\[연결 3\] BoardGraph (24칸 순환 트랙 & 탐색기)\
        > **

        -   TileNode: 0\~23번 타일 데이터 및 이벤트 관리

            -   TileAttachment: 타일 설치물 컴포넌트 (유희왕 뒷면 함정,
                > 부르마블 호텔, 지뢰)

        -   BoardEntity: 보드 위를 움직이는 모든 객체의 부모 추상
            > 클래스

            -   PlayerPawn: 플레이어 소유 기물 6계열 (윷말, 체스, 장기, 모노폴리,
                > 바둑, 쇼기)

            -   NeutralNPC: 중립 소환수 (카탄의 도적떼, 팩맨 고스트 -
                > 라운드 종료 시 BFS 최단 거리 AI 이동)

### **2.3. 멀티플레이어 패킷 동기화 흐름 (Sequence Flow)**

> **현행 구현(락스텝):** 아래 1~5는 최초 설계(호스트가 상태를 방송하는 방식)이고, 실제 게임 화면의 온라인 대전은 **락스텝**으로 구현되어 있다. 모든 참가자가 같은 시드로 같은 `TurnManager`를 각자 돌리고, 방장이 모든 행동(사람·봇·타임아웃)에 순서를 매겨 똑같이 적용시킨다(`NetGame`, 4.5의 "온라인 대전 동기화" 참고). 최초 설계의 `_rpc_sync_state`(상태 스냅샷 방송)는 코어에 남아 있지만 온라인 판에서는 쓰지 않는다. 연결은 WebRTC 직접 연결이며 시그널링은 공개 Pub/Sub(ntfy.sh)로 자동 처리한다(5자리 방 코드).

1.  **\[주사위 요청\]** Client A(턴 유저) → Host(서버): 주사위 굴림 및
    > 이동 요청 RPC 전송

2.  **\[법전 파이프라인 통과\]** Host: RuleBookManager의 4슬롯 패시브
    > 교칙을 순서대로 통과시켜 최종 이동 칸수 확정

3.  **\[개입 타이밍 A (3.5초)\]** Host → 전체 클라이언트: 주사위 결과
    > 브로드캐스트 및 3.5초간 즉발 생떼 카드 개입 대기

4.  **\[한 칸씩 이동 및 함정 판정\]** Host: 기물이 한 칸씩
    > 이동(Step-by-Step)할 때마다 해당 TileNode의 TileAttachment(은신
    > 함정) 유무 검사

    -   유희왕 함정(거울의 힘 등) 감지 시: 즉시 남은 이동력을 0으로
        > 만들고, 전체 클라이언트에 함정 발동 컷신 재생 후 기물을
        > 출발선으로 복귀시킴

5.  **\[중립 NPC 페이즈\]** 라운드 마지막 턴 종료 시, Host에서 카탄의
    > 도적 등 NeutralNPC의 AI 이동(BFS 탐색) 연산 수행 후 최종 보드 상태
    > 동기화

### **2.4. 클라이언트 · 온라인 · 배포 아키텍처 (v3.0)**

| 계층 | 구성 요소 | 책임 |
|---|---|---|
| 규칙 코어 (`core_engine/`) | `TurnManager`(8단계 FSM, 락스텝 지원) · `GameState` · `MoveExecutor` · `PawnSkills` · `BotBrain/BotController` | UI를 모르는 순수 규칙. 모든 행동은 `act()`로만 들어오고 시그널로 결과를 알린다 |
| 화면 (`scenes/`) | `MainBoard`(HUD·보드·연출) · `StartMenu`/`Lobby`(`LobbyTheme` 공통 부품) · `AvatarSlot/AvatarCatalog` · `RollPad/RollPresenter` · `EventAnnouncer` · `MobileSupport` · `UiSkin` | 코어의 시그널을 받아 그리고, 사용자 입력을 `act()`로 되돌린다 |
| 세션 (`GameSession`) | 정적 설정: 닉네임·AI 인원(1~3)·로비 의도(비밀/랜덤)·아바타·보드 시점·연출 멈춤·온라인 설정 | 화면 사이 전달, `user://profile.cfg`·`user://settings.cfg` 저장 |
| 온라인 (`NetGame` + 로비) | `LobbyService`(WebRTC 스타 연결) · `RoomCode/RoomSignaling` · `SignalBroker`(`NtfyBroker`/`MemoryBroker`) · `MatchBeacon/QuickMatch` | 5자리 방 코드로 연결하고 락스텝으로 같은 판을 진행 |
| 배포 | GitHub Actions(`deploy-web.yml`) → `gh-pages` 브랜치 → Vercel(`vercel.json`, 운영 `https://trickcal-board.vercel.app/`) | 푸시마다 테스트 → Godot 웹 내보내기(`export_presets.cfg`) → 정적 호스팅 |

- **클라이언트 상대 좌석 매핑:** 화면을 보는 플레이어(`local_player_id`)는 항상 **우측 하단**에 크게 앉고, 나머지는 턴 순서대로 우측 상단 → 좌측 하단 → 좌측 상단에 앉는다 (`MainBoard._compute_seats`). 온라인에서 P2~P4로 접속해도 내 자리는 우측 하단이다.
- **1P vs 3AI 봇 모드:** 훈련(`GameSession.MODE_AI`)은 나 + 컴퓨터 1~3명(`ai_opponents`)이고, 봇(`BotController`)은 사람과 같은 `act()` 권한 검증을 통과한다. 수동 4인 조작 모드는 개발용으로 메뉴에 남아 있다.
- **락스텝 온라인:** 같은 시드·같은 `TurnManager`를 각자 돌리고 방장이 행동 순서를 매겨 방송한다 (4.5 "온라인 대전 동기화"). 상태 지문(`state_hash`)으로 어긋남을 감지한다.
- **5자리 방 코드와 자동 시그널링:** 방장은 5자리 코드를 받고, WebRTC 접속 정보는 공개 Pub/Sub 릴레이(기본 `ntfy.sh`, 토픽 `trg_sig_{코드}_o{좌석}`/`_a{좌석}`)로 자동 교환된다. 사용자가 코드를 복사·붙여넣는 수동 연결은 없다.
- **빠른 랜덤 매칭:** 대기열 토픽 `trg_matchmaking_queue_v1`의 비콘으로 열린 방을 찾아 들어가거나 직접 방을 열고, 15초 뒤 빈자리를 AI로 채워 시작한다 (`QuickMatch`).
- **Vercel 웹 배포:** 빌드 산출물(`build/web`)을 `gh-pages`에 올리고 Vercel이 그 브랜치를 Production으로 호스팅한다. `vercel.json`이 캐시 헤더와 `.wasm` 타입을 지정한다. 웹은 가로 화면 전용이다(4.5).

## **3. 인게임 보드(24칸 사각 순환 트랙) 및 8단계 턴 상태 머신**

### **3.1. 24칸 순환 트랙 인덱스 규칙 (부르마블형, v3.2)**

윷놀이 지름길(29칸)을 없애고 **가운데가 뻥 뚫린 24칸 사각 외곽 트랙**(`TILE_COUNT = 24`, 한 변 6칸)으로 개편했다. 화면 좌표는 `BoardLayout`의 0~1 평면 좌표로 정의되고, 진행 방향은 **0번(우측 하단)에서 시작해 반시계 방향**(`0 → 1 → ... → 23 → 0`)이다. 규칙·좌표는 시점(탑뷰/기울인 탑뷰)과 무관하며 `MainBoard._project()`만 시점을 안다. 분기·대각선 타일은 없고 `TileNode.next_default` 하나로 이어진 단일 고리다.

-   **네 모서리 코너 (큼직한 1.25배 팔각 타일):**

    -   0번 (우측 하단): **출발 / 결승** (START_GOAL). 모든 플레이어가 공유하므로 시점이나 좌석에 따라 돌리지 않는다.

    -   6번 (우측 상단): **점프 코너 1** - 정확히 멈추면 10번으로 즉시 +4칸 점프.

    -   12번 (좌측 상단): **반환점 코너** (트랙의 절반). 폰 승급·쇼기 나리 승급 기준점이고 팩맨 고스트가 소환되는 곳.

    -   18번 (좌측 하단): **점프 코너 2** - 정확히 멈추면 21번으로 즉시 +3칸 점프.

-   **특수 타일 (TileType):** BAKERY(빵집: 생떼 카드 획득) `4, 10, 14, 20번`, PORTAL(옷장 포탈) `9번`(도착 시 보드를 가로질러 16번으로 워프)·`16번`(도착 시 20번으로 워프), 나머지(`1, 2, 3, 5, 7, 8, 11, 13, 15, 17, 19, 21, 22, 23번`)는 NORMAL.

-   **점프·워프 규칙:** 점프 코너와 옷장은 **정확히 멈췄을 때만** 작동하고 스쳐 지나가면 발동하지 않는다. 워프 도착 칸에서 다시 워프하지는 않지만(9→16에서 16의 포탈은 다시 타지 않음) 도착 칸이 빵집(10·20번)이면 카드를 받는다. 법전 `LAW_01 지름길 공사 중`이 있으면 점프 코너와 옷장이 모두 작동하지 않는다. 무인도에 갇힌 말은 점프하지 않는다. 필살기(비행기 직항·알까기 안착)로 도착한 칸은 점프·워프를 다시 타지 않는다. 체스 비숍·쇼기 각행은 코너(6·12·18번)를 스치거나 멈추면 이동 거리가 +2칸이다.

-   **완주:** 0번을 정확히 밟거나 넘을 때이며 `LAW_08`이 있으면 남은 눈금만큼 튕겨 나온다. 0번에서 빽도로 후퇴하면 말이 회수되어 출발 대기로 돌아간다 (역주행 중에만 23번으로 후퇴하며, 이후 한 바퀴를 더 돌아야 완주한다). 후퇴 눈금(음수)에는 아직 출발하지 않은 말을 고를 수 없고(역주행 중 제외), 이미 출발했다가 0번에서 뒤로 물러난 말(`retreated_run`)은 역주행 상태가 아니면 0번을 한 번 더 지나가기 전까지 완주하지 못한다 (0번을 밟아도 멈출 뿐, 지나가면 표시가 풀린다).

-   **중앙 오픈 스테이지:** 안쪽에는 타일이 없다. 굴리기 버튼(120px)과 파워 게이지, 주사위·룰렛·화투·마작·타로 연출, 카드 드롭 존과 발동 배너가 모두 이 빈 공간에서 재생되어 타일을 가리지 않는다. 일반 타일은 슈퍼타원 모양의 큼직한 둥근 사각형(한 변 0.108 = 56px), 코너는 1.25배 팔각형이고 점프 코너에는 목적지를 가리키는 화살표가, 반환점에는 깃발이 그려진다 (`BoardSkin.definition`).

    > 드래프트 (15초)

3.  PHASE_ROLL_WAIT: 주사위/포커/룰렛 등 판정 도구 실행 대기 (10초).

4.  PHASE_INTERRUPT_ROLL: \[개입 타이밍 A\] 주사위 결과 조작계 생떼 카드
    > 개입 대기 (3.5초)

5.  PHASE_SELECT_PAWN: 이동할 내 기물(1\~4번) 선택 (10초)

6.  PHASE_MOVING_STEP: 기물이 한 칸씩 이동하며 실시간으로 타일 설치
    > 함정(TileAttachment) 및 중앙 법전 룰 체크. 도착 직전 \[개입 타이밍
    > B\] 체크

7.  PHASE_RESOLUTION: 말 업기, 말 잡기(추가 턴), 승리 조건(내 말 4개 완주) 체크

8.  PHASE_NEUTRAL_NPC: (라운드 마지막 턴 종료 시) 보드 위의 카탄의 도적
    > / 팩맨 고스트 등 중립 NPC들이 자동 이동 및 사냥 수행. 기물을
    > 한 번 잡은 NPC는 판에서 사라진다.

## **4. 콘텐츠 및 밸런스 데이터 시트 (Data Tables v3.0)**

### **4.1. 보드게임 근본 기물(Pawn) 6종, 세부 기물(SubType), 상시 능력과 1회용 필살기**

세트 효과(2세트·4세트 시너지)와 세트 특수 승리는 **전면 삭제**했고 이 문서의 표에도 없다. 특정 기물만 모으게 강요하고 알아야 할 규칙이 너무 많았기 때문이다. 대신 개별 기물 자체의 상시 능력과 **1회용 고유 필살기(Active Skill)**에 힘을 실었다. 승리 조건은 **내 말 4개를 모두 완주**시키는 것 하나뿐이다 (생떼 카드 효과로 말이 완주해도 똑같이 센다).

증강 드래프트는 세부 기물(`PawnSubType`)을 하나씩 지정해서 지급한다 (예: [장기] 포 지급). 이미 가진 기물은 받을 수 없어서 같은 병종이 겹치지 않는다 (윷말은 4개, 바둑돌은 흑·백 각 2개까지). 쇼기를 더해 기물 지급 증강은 세부 기물 19종이다.

**모치고마 낙하 세부 규칙:** 원 명세의 "이 말로 적을 잡은 적이 있다면(또는 내 턴 시작 시)"는 필살기를 쓸 수 있는 시점이 항상 내 턴 굴리기 전이라 조건 없이 쓸 수 있는 것으로 구현했다. 대기 말이 없거나 낙하할 자리가 없으면 쓸 수 없다 (거부되며 사용 완료로 처리되지 않는다). 낙하 자리는 보병이 온 길의 직전 타일이다.

**1회용 필살기 5종 요약 (`PawnSkills`, `PawnCatalog.SKILL_IDS`):**

| 필살기 | 기물 | 조작 방식 | 결과 |
|---|---|---|---|
| 진짜 알까기 슈팅 (`shoot`) | 바둑:흑돌 | 슬링샷 조준: 마우스를 누른 채 뒤로 당겼다 놓으면 반대 방향으로 파워만큼 발사 | 직선(충돌 반경)에 닿은 모든 적 말(업힌 말 포함)을 출발선으로 탈락, 흑돌은 멈춘 좌표에서 가장 가까운 타일에 안착 |
| 직선 전차 저격 (`charge`) | 장기:차 | 버튼 한 번 (즉시 돌진) | 전방 직선에서 가장 앞의 적 말을 잡음, 적이 없으면 다음 코너까지 |
| 단독 캐슬링 (`castle`) | 체스:룩 | 맞바꿀 아군 기물 선택 | 굴리기 전에 내 다른 기물과 위치를 맞바꿈 |
| 직항 워프 (`warp`) | 모노:비행기 | 빵집(4·10·14·20) 또는 코너(6·12·18) 타일을 클릭 | 주사위 대신 그 타일로 즉시 이동 |
| 모치고마 낙하 (`drop`) | 쇼기:보병 | 버튼 한 번 (출발선 대기 말이 자동 선택) | 대기 중인 내 말 1개를 보병 바로 뒷칸(뒤가 출발선이면 앞칸)에 즉시 낙하, 도착 처리 정상 적용 |

봇(`BotBrain`)도 같은 필살기를 쓴다: 적을 많이 맞히는 알까기 각, 앞선 적을 잡는 차 저격, 이득이 큰 워프, 위험할 때의 캐슬링.

#### 4.1.3. 공용 규칙 (업기·잡기)

- 업기와 잡기 추가 굴림은 **윷놀이 기물의 고유 능력**이다. 일반 기물(기본·체스·장기·모노폴리·바둑)은 아군과 같은 타일에 도착해도 합쳐지지 않고 따로 공존하며, 상대를 잡아도 추가 굴림이 없다.
- **개별 피격:** 업힌 기물은 하나의 묶음이라 잡히면 전원이 함께 출발선으로 추방된다. 업히지 않고 같은 타일에 따로 서 있는 말은 적이 도착해도 적 주인마다 1개(ID가 앞선 말)만 잡히고 나머지는 살아남는다. 지뢰 폭발 같은 광역 효과와 흑돌 알까기 슈팅은 그 칸/직선의 모든 말에 적용된다.

### **4.2. 판정 도구 (주사위 & 카드 딜러) 10종**

### **4.4-b. 시작 허브·대기방 UI (원본 로비 느낌, v3.3)**

원작(트릭컬 리바이브)의 마을 메인 화면 구성을 참고하되, **원작 그림·아이콘은 쓰지 않고 모든 부품을 코드로 직접 그린다** (`scenes/hub_kit.gd`의 `HubKit`). 팬게임 가이드라인상 원작 에셋을 저장소에 넣지 않기 위한 방침이다. 캐릭터 그림은 `content_trickcal/avatars/<id>/`에 들어오면 자동으로 대체된다 (없으면 색 원 + 웃는 얼굴).

- **시작 허브 (모드 선택, 개정):** 왼쪽에 로고 + 큰 내 아바타(`ProfileCapsule`) + 초록 닉네임 이름표(`ProfileName`) + `아바타 설정`(`AvatarButton`) + 작은 `이름 바꾸기`(`RenameButton`), 오른쪽에 `어디로 대결하러 갈까요?` 아래 가로로 긴 모드 카드 3장(`ModeColumn`)과 큰 노란 `바로 시작`(`QuickStartAi`, 마지막으로 고른 AI 인원과 곧바로 대결, 기본 3명). 위쪽에는 말풍선 팁 띠(`TipBar`, `>>` 다음 팁)와 둥근 `규칙`(`HubRules`)·`설정`(`HubSettings`) 버튼, 위에 늘어진 축제 등불과 햇살(`FestivalDecor`). 허브에서는 청록 위·아래 띠를 숨기지만 띠의 버튼은 살아 있다.
- **모드 이름 (v3.3):** `놀이터`(구 훈련, AI 1~3명, `TrainingCard`) / `친선 줘팸터`(구 비밀 결투, 방 코드 5자리 친선전, `SecretCard`) / `익명 줘팸터`(구 랜덤 결투, 15초 자동 매칭, `QuickCard`). 로비 위 띠 제목과 훈련 설정 화면 제목도 같은 이름을 쓴다. 코드의 `lobby_intent` 값(`secret`/`quick`)과 `MODE_*` 상수는 그대로다.
- **대기방(방 코드 / 랜덤 매칭 / 참가자 화면):** 좌석을 한 줄 행이 아니라 **캐릭터 자리 카드 4장**(`HubKit.seat_card`: 좌석 색 테두리, P번호, 방장 왕관, 큰 동그란 캐릭터, 이름표 `SeatTitle<좌석>`, 상태 줄, 아래 `AI 봇으로 채우기`/`내보내기`/`비우기` 버튼)으로 나란히 보여 준다. 빈 자리는 흐리고 모래시계가 깜빡이며, 입장하면 카드가 채워진다. 위쪽 등불 장식은 시작 메뉴와 같다.
- **테스트:** `ui_menu_test`가 허브 요소·팁 넘기기·둥근 버튼 팝업·`바로 시작`을, `ui_lobby_test`가 카드 4장 명단을 확인한다.

### **4.4-c. 규칙 도감 (v3.5)**

시작 허브·로비의 `규칙` 버튼과 게임 메뉴의 `규칙 책자`가 **인게임 도감 화면 느낌**의 팝업(`scenes/rulebook.gd`, 노드 이름 `Popup`)을 연다. 원작 그림은 쓰지 않고 구성만 참고해 전부 코드로 그린다. 왼쪽 위 초록 둥근 `<` 버튼(닫기)과 `규칙 도감` 제목, 위쪽 두 탭(`기본 규칙` 시작하기·한 턴·보드·잡기 / `도감` 도구·말·카드·법전), 왼쪽 세로 항목 줄(청록 알약 + 동그란 아이콘, 고른 항목은 흰 알약), 갈색 가죽 테두리의 **줄 노트 쪽**(월계수 제목, 첫 글자를 주황색으로 키운 문단, 노란 꿀팁 쪽지, 오른쪽 위 금 메달)과 오른쪽 **하늘색 카드 칸**(카드마다 아이콘 + 이름표 + 설명, 스크롤), 양옆 초록 화살표(이웃 장 이름 표시), 아래 주황 리본 쪽 번호(`n / 8`)로 구성된다. ← → 키로 장을 넘기고 ESC로 닫는다. 말투는 `~해요`로 쉽게 쓰고 문단을 짧게 끊었다.

| 장 | 노트 | 카드 |
|---|---|---|
| 시작하기 | 한 줄 소개, 이기는 법, 준비물 | 재미 세 가지 + 눈금 공정 |
| 한 턴 | 재굴림·빽도·증강 주기·제한 시간 | 카드 / 굴리기 / 말 고르기 / 정산 (번호 카드 4장) |
| 보드 | 24칸 설명과 눈여겨볼 칸 | **미니 보드 그림**(번호, 점프·워프 화살표, 범례) |
| 잡기 | 잡기·업기·완주 | 자주 묻는 질문 4장 |
| 도구 | 고르는 요령 | 10종 도구 카드 |
| 말 | 필살기 5종 | 여섯 계열 카드 |
| 카드 | 사용법과 색 구분 | 16종 카드 (문구는 `MainBoard.CARD_SUMMARIES`·`display_name`에서 읽음) |
| 법전 | 증강 4종류와 법전 규칙 | 교칙 8종 (`LawRegistry`에서 읽음) |

카드·교칙 문구는 코드에서 읽어 오므로 바꾸면 도감도 따라간다. 도구·말·보드 설명은 손으로 쓴 글이라 규칙을 바꿀 때 `Rulebook._ch_*`도 함께 고친다. `ui_menu_test`가 8장 구성, 넘기기, 카드·교칙 이름 포함을 검사한다.

### **4.5. 화면 구성과 조작 (UI/UX, 1366x768)**

- **화면 비율 대응:** 디자인 기준은 1366x768이고 스트레치는 `expand`라 창이 더 넓거나 높아도 UI가 잘리지 않고 남는 공간을 나눠 쓴다. HUD는 세 묶음으로 나뉜다: 왼쪽(프로필 2개·법전·모드/새 게임), 가운데(보드·리본·카드 독·알림), 오른쪽(프로필 2개·판정 도구 카드·굴리기·기물 독·상단 버튼·서랍). 넓은 창에서는 왼쪽 묶음은 왼쪽 끝, 오른쪽 묶음은 오른쪽 끝에 붙고 보드는 가운데에 서며, 높은 창에서는 전부 세로 가운데로 간다. 가장자리에서 12px의 안전 여백을 두어 모서리가 둥근 폰·베젤에서도 잘려 보이지 않는다.
- **가로 고정(웹 셸):** `project.godot`의 `handheld/orientation`을 가로(1)로 두고, 웹 `head_include`에 CSS(세로일 때 전체 화면 "화면을 가로로 돌려 주세요" 덮개)와 첫 터치 때 `screen.orientation.lock("landscape")`를 시도하는 스크립트를 넣었다. 브라우저가 잠금을 거부해도(iOS 등) 덮개가 세로 플레이를 막는다.
- **모바일 대응 (1차):** 가로 화면 전용(`MobileSupport`): 세로 창이면 "화면을 가로로 돌려 주세요" 안내로 가리고, 터치 기기·웹에서는 `전체화면` 버튼(웹은 가로 고정 시도)을 보여 준다. 웹 셸은 확대·스크롤·롱프레스 메뉴를 막는다 (`export_presets.cfg`의 `html/head_include`). 터치는 Godot의 마우스 에뮬레이션으로 클릭·드래그·꾹 누르기 게이지가 그대로 동작한다. 레이아웃은 1366x768을 비율 유지로 축소해 쓰므로 작은 폰에서는 UI가 작게 보이며, 터치 크기에 맞춘 컴팩트 레이아웃은 후속 과제다.
- **시작·로비 UI (밝은 민트/청록 테마, 레퍼런스: 갓필드식 로비):** 모든 시작·로비 화면은 `LobbyTheme`의 공통 부품을 쓴다 - 구름무늬 민트 배경, 위쪽 청록 띠(`[←]` 뒤로가기 / 화면 제목 / `[규칙]`), 아래쪽 청록 띠(내 이름 `○○ 교주님` / `[설정]`), 노란 연두색 입력창, 이중 테두리 큰 버튼, 크림색 시작 버튼, 둥근 팝업. 흐름: (1) **타이틀:** 게임 로고 + `교주의 이름` 입력(1~10자, 앞뒤 공백 제거, `user://profile.cfg`에 저장해 미리 채움) + `[입장하기]`. (2) **모드 선택:** 큼직한 카드 3장 - `[훈련]`(파랑, 컴퓨터 1~3명) / `[비밀 결투]`(초록, 방 코드 5자리 친선 대결) / `[랜덤 결투]`(분홍, 15초 자동 매칭). (3) **훈련:** `AI 상대 N명`(1~3) 선택 후 `[게임 시작]` -> 메인 보드(나 vs 컴퓨터 N명, 참가자 수에 맞춰 좌석 배치). `[비밀 결투]`는 로비 씬의 방 코드 입력 화면(`방 코드` 입력 + `[입장하기]` + `[새 방 만들기]`), `[랜덤 결투]`는 로비 씬에서 곧바로 빠른 매칭을 시작한다(`GameSession.lobby_intent`). 이미 이름을 정했다면(게임·로비에서 돌아왔을 때) 모드 선택부터 보인다. 위쪽 띠의 `[규칙]`은 규칙 요약 팝업, 아래쪽 `[설정]`은 전체화면·연출 멈춤·보드 시점 팝업. 게임 중 `메뉴` 버튼으로 시작 화면으로 돌아올 수 있고 닉네임과 모드는 `GameSession`이 화면 사이에서 전달한다.

- **좌석 (Client-Relative Seating, 네 모서리):** 화면을 보는 플레이어(`local_player_id`, 기본 P1)는 항상 **우측 하단**(크게)이고, 다음 순서는 우측 상단, 맞은편은 좌측 하단, 이전 순서는 좌측 상단에 앉는다 (`MainBoard._compute_seats`, 앵커 `me/right/top/left` - `top`이 좌하단). 2인 대전의 상대는 우측 상단, 3인은 우측 상단·좌측 상단이다. 멀티플레이에서 P2~P4로 접속해도 본인이 우측 하단이다.
- **플레이어 프로필 카드 (네 모서리, 미니멀):** 상대 카드는 좌측 84x84 아바타 액자, 우측 상단 이름과 카드 수(`x1`), 우측 하단 2x2 기물 상태 슬롯이다. **내 카드(`ME_PROFILE_SIZE` 340x164)는 더 크다:** 96px 아바타 + 기물 4칸 한 줄이고, 필살기를 가진 기물 칸 아래에 `필살기` 버튼이 붙는다. 슬롯은 배경·테두리만으로 [대기(어두운 회색·반투명) / 출전(플레이어 색) / ★완주(황금빛)]를 구분한다. 완주 구슬·도구 이름·사도 번호 같은 글줄은 두지 않는다.
- **스포트라이트 (현재 턴 표시):** 현재 턴이 아닌 프로필은 `modulate (0.42, 0.42, 0.45, 0.85)`로 어둡게 가라앉고, 현재 턴 프로필은 `(1.1, 1.1, 1.1, 1.0)`으로 밝아지며 외곽 광채와 함께 1.05배로 살짝 커진다. 누구 턴인지 글씨로 읽지 않는다.
- **중앙:** 24칸 사각 보드판(우하단 0번 출발, 반시계, 진행 방향 화살표, 말 호버 시 도착 경로 미리보기, 업힌 개수 배지). 상단에는 슬림한 리본(`라운드 | 현재 턴 | 진행 방향`) 한 줄만 둔다. 보드판 아래에는 굴리기 버튼과 개입 패스 같은 필요한 버튼만 두고 긴 안내 문구는 없다.
- **좌측 중앙:** 엘리아스 중앙 법전 (4슬롯, 빈 슬롯은 점선).
- **보드판과 굴리기 (모바일 대응 배치):** 보드는 584x584 받침 판에 520x520 타일 영역으로 화면 높이의 대부분을 차지한다 (일반 타일 56px, 코너 70px). 굴림 조작은 도구 종류에 따라 다르다. **차징형(기본 주사위·윷·친치로)**은 중앙 오픈 스테이지(타일이 없는 보드 한가운데) 아래쪽의 지름 120px 둥근 `굴리기` 버튼 (파워 게이지는 그 바로 아래)을 꾹 눌러 파워 게이지를 채우고 손을 떼어 굴린다 (《모두의 마블》의 ROLL 버튼 자리). **그 외 도구는 보드 한가운데에 크게** 보여 준다: 인생게임 룰렛은 지름 약 270px 원판을 손가락/마우스로 잡고 빙글 돌려 놓으면 돌린 속도만큼 돌다가 엔진이 정한 눈금에서 멈추고(가볍게 톡 쳐도 기본 세기), 러시안 룰렛은 큼직한 리볼버의 방아쇠를 눌러 당기며(빈 총이면 약실이 돌고 비운 칸이 표시, 실탄이면 총구 번쩍), 홀덤·슬롯은 지름 190px 큰 버튼(`카드 뽑기`/`레버 당기기`)을 누른다. 눈금·결과는 언제나 엔진이 정하고 조작은 연출 세기에만 쓰인다. `멈추고 이동 확정`/`개입 패스`/`폭탄 떠넘기기`는 우측 판정 도구 카드 아래 작은 버튼이다. 생떼 카드 독은 하단 중앙에서 카드를 80x110으로 줄였다.

- **증강 선택 연출:** 증강 카드를 누르면 바로 적용하지 않고 선택한 카드가 커지며 반짝이고 나머지는 어두워지는 연출(`선택 완료!`, 0.9초)을 보여 준 뒤 다음 단계로 넘어간다. 말을 골라야 하면 이어서 말 아이콘 카드 선택 화면이 뜨고, 말 카드도 누르면 같은 연출(0.7초) 뒤 적용된다. 말 고르기를 취소하면 증강 카드 3장 화면으로 돌아간다.

- **텍스트 압축 원칙 (v3.1):** 인게임 설명은 서술어를 빼고 `키워드 + 명사형 종결(1~2줄, 25자 내외)`로 쓴다. 기호(`+`, `→`, `↔`, `&`)와 키워드(`처치`, `재굴림 +1`, `관통`, `[1회]`)로 줄이고, 글꼴에 없는 `➔`·`⚡`·이모지는 쓰지 않는다. 적용 범위: 중앙 법전 8종(한 줄), 생떼 카드(작은 카드 = `CARD_SHORT` 15자 이내 1줄 / 2.5배 확대(350x490) = `CARD_SUMMARIES` 개조식 + `◆ 타이밍`·`◆ 사용` 2줄 + 사용 가능 여부), 증강 카드(`◆ 기본 말 1개 → [세트] 기물` / `◆ 패시브` / `◆ [1회] 필살기`, 글자 17pt), 기물 툴팁(`◆ 패시브` / `◆ [1회] 필살기명` + 한 줄 설명, 19~22pt), 우측 판정 도구 전광판(한 줄 규칙 + 규칙표 + 12pt 보충). 문구는 코드 한 곳씩 고친다: 법전 `description`, `PawnCatalog.SUB_ABILITIES/SKILL_TEXTS`, `MainBoard.CARD_SHORT/CARD_SUMMARIES/TOOL_CARDS/TOOL_RULES`.
- **연출 순서 원칙:** 한 사건에서 여러 일이 동시에 터지지 않게 순서를 정한다. 잡기는 [내리찍기 -> 충격 -> 프로필 반응 -> 날아감 -> 착지], 함정은 [충격 -> 반응 -> 날아감], 증강은 [`라운드 N` 카드 -> 증강 선택 창 -> 선택 후 일괄 공개] 순서다 (`EDGE_CASE_SPEC.md` "연출 순서").
- **다음 턴은 연출이 끝난 뒤에:** 잡기 같은 말 움직임 연출 중에는 `[N 차례]` 알림과 프로필 턴 강조를 미루고, 연출이 끝나면 넘어간다 (잡음 -> 타격 -> 날아감 -> 다음 턴 순서).
- **증강 공개는 한꺼번에:** 라운드 시작 드래프트에서 각자 고른 증강을 한 명씩 공개하면 늘어지므로, 모두 고른 뒤 `선택한 증강` 카드 한 장에 P1~P4가 고른 증강을 **선택 카드 그림 그대로** 나란히 보여 준다 (`_draft_summary`, 글자 목록 아님). 이어서 `N라운드 시작!` 타이틀이 1.2초 떴다 사라지고 굴리기가 시작된다. 증강으로 생긴 교칙은 별도 `새 교칙` 카드를 띄우지 않고 법전 슬롯 연출만 보여 준다. 선택 자체는 로그에 한 줄씩 남는다.
- **게임 시작 오프닝 (`OpeningSequence`, 클릭하면 건너뜀):** 게임을 시작하면(로비·새 게임) 증강 선택 창을 바로 띄우지 않고 3단계를 먼저 재생한다. ① **중앙 대진표(약 1.7초):** 참가자 프로필 카드(아바타·이름·나/AI/참가자)가 좌석별로 `TRANS_BACK`으로 슬라이드 인해 중앙에 `VS`로 이어진다 (로딩 게이지·팁 없음). ② **프로필 자리로 이동(0.7초):** 카드가 작아지며 각자 모서리 프로필 자리로 날아가 사라지고 오버레이가 걷힌다. ③ **`레이스 시작!`(약 1초):** 가로지르는 리본 타이틀(부제 `GAME START! - 초증강 엘리아스 마블 개막!`)이 쾅 찍힌 뒤 사라지고, 곧바로 증강 카드가 아래에서 솟아오른다. 오프닝 중에는 증강 창·봇·입력이 잠기고(`_intro_blocks()`), 테스트용 즉시 모드(`instant_roll_for_test`)에서는 건너뛴다. 이모지는 글꼴에 없어 인게임 문구에는 쓰지 않는다.

  1. **걸음:** 한 칸 0.14초 아치형 점프(`HOP_HEIGHT` 20px) -> 착지 시 `Bounce` 노드가 `(1.25, 0.78)`로 납작해졌다가 `TRANS_BACK`으로 탱글하게 복원 -> 밟은 타일이 환해졌다 0.45초에 걸쳐 원래 색으로(`_tile_glow`).

  - **흑돌 알까기:** 뒤로 살짝 당김 -> 직선 발사(맞은 말은 닿는 순간 충격 링 + 발사 방향으로 튕기며 회전) -> 멈춘 자리에서 가까운 타일로 자리 재조정. 튕긴 말은 이어서 포물선으로 출발선까지 날아간다.
  - **일반 규칙:** 상태가 바뀌어 말의 자리가 달라지면 순간이동 대신 포물선 이동(`_settle_pawn_view`/`_glide`)으로 보여 준다. 잡힌 말은 충격 링 -> 빙글 회전하며 출발선으로, 순간이동(옷장·비행기·탑 흩어짐)은 높이 떠올라 날아가 내려앉고, 위치 교환(룩 캐슬링·수레바퀴)은 두 말이 위/아래로 엇갈려 지나가고, 모치고마 낙하는 위에서 떨어지고, 도미노 밀림은 미끄러지고, 완주·업기는 목적지까지 간 뒤 사라진다. 중립 기물도 미끄러져 움직인다.
  - 움직이는 동안 입력과 봇은 잠기고(`_fx_until_msec`) 연출 속도 배율(최대 2배)을 따른다. 테스트용 즉시 모드는 예전처럼 순간 이동한다.
- **행동 사이의 호흡:** 행동이 바로바로 이어지지 않도록 이동이 끝나면 0.8초 멈추고, 새 플레이어의 턴에는 `[P2 차례]`(내 턴은 `내 차례!`) 알림이 0.9초 뜬다. 봇은 턴 시작 0.8초 → 굴리기 직전 0.6초 → 굴림 결과 확인 1.0초 → 말 이동 0.9초 순으로 호흡을 둔다.
- **멀티플레이 로비 (5자리 방 코드 자동 연결):** 시작 메뉴의 `[비밀 결투]` → `방 코드 입력` 또는 `새 방 만들기`. 방장은 영문 대문자+숫자 5자리 방 코드(헷갈리는 `0 O 1 I L` 제외 31자)를 받고 화면에는 황금색 `[ 방 코드: XXXXX ]` 배지·`코드 복사` 버튼·P1~P4 좌석 상태(`방장` / `입장 대기 중...` + `AI 봇으로 채우기` / `입장 완료!` / `AI 봇`)만 보인다. 참가자는 방 코드 5자리 입력창 하나와 `입장하기` 버튼만 보며 `연결 중... → 입장 완료!`로 들어간다. 긴 WebRTC 접속 정보(`TRG1-...` 코드)는 **공개 Pub-Sub 릴레이(기본 `https://ntfy.sh`, 가입·API 키 없음)** 를 통해 자동으로 교환되고 사용자에게 보이지 않는다. 릴레이에 닿지 못하면 안내 문구만 보여 주며, **초대/응답 코드를 직접 복사·붙여넣는 수동 연결 UI는 제거했다**(10-16 결정: 자동 연결만 지원). 좌석은 `열림 / 초대 중 / 사람 / 컴퓨터` 네 상태이고 방장은 `내보내기`·`AI 봇으로 채우기`·`비우기`를 쓴다. 빈 자리는 시작할 때 봇으로 채운다. 
- **아바타 설정 (`AvatarCatalog`):** 모드 선택 화면의 `[아바타 설정]`에서 내 아바타를 고른다. 왼쪽에 큰 미리보기(+ 웃음/분노/놀람/환호 시험 버튼), 오른쪽에 고를 수 있는 아바타 격자(지금 8개 자리표시자: 색·번호), 아래 `[선택 완료]`. 선택은 `GameSession.avatar_id`로 `user://settings.cfg`에 저장되고 훈련·방 슬롯·게임 프로필(`AvatarSlot`)에 쓰인다. 온라인에서는 참가자가 방장에게 `_hello(닉네임, 아바타)`로 알리고 방장이 명단(`LobbyModel`의 좌석별 `avatar`)과 시작 설정(`avatars`)으로 모두에게 전달해 모든 화면에서 같은 아바타가 보인다. 컴퓨터(AI) 좌석의 아바타는 좌석 번호로 정해져(`AvatarCatalog.bot_avatar`) 모든 화면에서 같고 사람이 고른 것과 겹치지 않게 피한다. 실제 그림은 `content_trickcal/avatars/<id>/`에 넣고 `AvatarCatalog.ENTRIES`에 한 줄 추가하면 선택 화면에 나타난다. 방 슬롯 줄에도 작은 아바타(34px)가 붙는다.
- **멀티플레이 메뉴와 빠른 랜덤 매칭:** 모드 선택의 `[랜덤 결투]`가 빠른 랜덤 매칭이고 `[비밀 결투]`가 방 코드 입장/방 만들기다(위 시작·로비 UI). 빠른 매칭(`QuickMatch`)은 공용 대기열 토픽 `trg_matchmaking_queue_v1`을 쓴다: (1) 최근 12초(`since=12s`) 안의 `OPEN_ROOM` 비콘(`{"type","code","players"}`)에서 자리가 남은 방(인원이 많은 방 우선, 같으면 작은 코드)을 골라 방 코드 자동 입장 -> (2) 없거나 입장에 실패하면 내가 P1이 되어 공개 방을 만들고 3초마다 비콘을 올림 -> (3) 대기 시작 후 15초가 지나거나 4명이 차거나 `지금 바로 시작`을 누르면 `ROOM_CLOSED` 비콘을 남기고 빈자리를 AI 봇으로 채워 시작 신호를 보냄. 대기 화면은 `매칭 중... 다른 교주님을 찾고 있습니다 (경과 시간: N초)`와 남은 시간·인원(n/4)·P1~P4 자리를 보여 준다. 동시에 방을 판 두 사람은 방장 대기 중 3초마다 대기열을 다시 읽어 코드가 더 작은 방이 있고 내 방에 아직 나 혼자면 코드가 큰 쪽이 그 방으로 옮긴다(서로 엇갈려 옮기지 않음).
- **게임 시작과 인원:** 방장 혼자면 컴퓨터 대전(빈자리 3명 전부 AI, 기존 `GameSession.MODE_AI`). **사람이 둘 이상이면 온라인 대전**: 지금 명단 그대로(사람 + 방장이 `AI 봇으로 채우기`를 누른 자리) 시작하고 비어 있거나 초대 중인 자리는 빠진다. 그래서 **AI 없이 2인 대전**(`시작 버튼: 사람 2명, AI 없음`)도 되고 3인/4인, 사람+AI 혼합도 된다. 빠른 랜덤 매칭은 15초 뒤 남은 자리를 AI로 채워 시작한다. 시작 버튼 문구는 현재 구성(`게임 시작 (사람 2명 + AI 1명)` 등)을 보여 준다.
- **릴레이 요청 수:** 공개 ntfy.sh는 요청 횟수 제한(처음 60회, 이후 5초에 1회)이 있어 여러 주제를 쉼표로 묶은 한 번의 요청(`fetch_many`)으로 읽고, 방장의 응답 수거 간격은 방 변화 후 20초 동안 2초, 이후 5초로 늘린다.
- **온라인 대전 동기화 (락스텝):** 모든 참가자가 **같은 시드**로 **같은 규칙 엔진(`TurnManager`)을 각자 돌리고**, 방장이 모든 행동(사람·봇·타임아웃)에 순서 번호를 매겨 똑같이 적용시킨다(`NetGame`). 판 상태나 이벤트를 따로 보내지 않으므로 말 이동·굴림 연출·로그가 모든 화면에서 같은 코드로 재생된다. 규칙: (1) `TurnManager.lockstep`이면 모두가 규칙 권한을 갖고 `act()`/`force_timeout()`/`auto_pick_draft()`는 `action_interceptor`를 통해 방장으로 간다. (2) 방장은 보낸 사람이 그 좌석의 주인인지(봇 좌석은 방장만) 확인하고, 이동 연출(`PHASE_MOVING_STEP`) 중이면 쌓아 두었다가, 규칙이 받아들인 행동만 `{seq, serial, action, params, check}`로 방송한다(거부된 행동은 보낸 사람에게만 사유를 돌려줌). (3) 참가자는 항목의 `serial`(그 시점의 `phase_serial`)이 자기 판과 같고 이동 연출이 아닐 때만 적용한다. (4) 제한 시간은 방장만 판단하는 `__timeout{serial}` 행동으로 복제되며 serial이 다르면(이미 지난 단계) 무시한다. 온라인은 제한 시간이 3배(`TIMER_SCALE`). (5) 항목마다 상태 지문(`state_hash`: 스냅샷+RNG 상태+단계)을 보내 어긋나면 `desynced`로 알린다. (6) 시작: 참가자가 화면을 만든 뒤 준비 신호를 보내고 방장이 모두 준비되면(최대 15초, 안 온 사람은 봇) `started(seed, players, bots)`를 보내 각자 `start_game`한다. (7) 누군가 나가면 방장이 `__takeover{seat}`를 모두에게 보내 그 자리는 컴퓨터가 이어받는다(방장의 `BotController`가 조종). 방장이 끊기면 참가자는 안내 창과 `메뉴로 돌아가기`가 뜬다. (8) 1초마다 핑을 주고받아 상대 화면이 4초 넘게 멈추면(다른 창·탭·앱으로 이동 등: 웹 브라우저는 보이지 않는 탭을 멈춘다) 상단에 안내를 띄운다. 온라인에서는 새 게임·모드 전환·치트/디버그를 숨긴다(상태를 직접 바꾸면 판이 어긋남).
- **추가 구조:** `NetGame`(락스텝 동기화) · `MatchBeacon`(비콘 형식·고르기·양보 규칙) · `QuickMatch`(대기열 진행기) · `SignalBroker.fetch_many`(다중 주제·신선도 조회).
- **자동 시그널링 흐름:** 방을 만들면 방장은 빈 좌석(P2~P4) 몫의 초대(offer)를 모두 미리 만들어 토픽 `trg_sig_{방코드}_o{좌석}`에 `표식(nonce)\n초대코드`로 올리고, 응답 토픽 `trg_sig_{방코드}_a{좌석}`을 2초마다 읽는다. 참가자는 세 좌석의 초대 토픽을 읽어 열린 좌석(마지막 메시지가 닫힘 표식이 아니고 같은 표식의 응답이 아직 없는 좌석)을 찾고, 응답을 `표식\n응답코드`로 올린 뒤 1.2초 후 "내 응답이 그 표식의 첫 응답인가"를 확인해 동시에 같은 자리를 노린 경쟁에서 한 명만 이기게 한다(진 쪽은 다음 후보 좌석으로). 연결을 15초 안에 맺지 못하면 다음 후보로 넘어가고, 후보가 바닥나면 실패 안내를 띄운다.
- **로비 구조:** `RoomCode`(방 코드 생성·정규화·토픽 이름·표식 포장) · `SignalBroker`(릴레이 추상) · `NtfyBroker`(ntfy 호환 서버: `POST /{토픽}`, `GET /{토픽}/json?poll=1&since=all`, 서버 주소 교체 가능) · `MemoryBroker`(테스트용 가짜) · `RoomSignaling`(방장/참가자 교환 규칙) · `LobbyCode`(코드 형식) · `LobbyModel`(좌석 상태 모델, 단위 테스트) · `RtcLink`(연결 1개의 시그널링, ICE 후보를 모아 코드 하나에 담음) · `LobbyService`(WebRTCMultiplayerPeer 스타 연결: 방장 피어 1, 참가자 피어 = 좌석 번호, 닉네임·명단 RPC, 자동 초대/수거/재시도) · `Lobby`(화면). 공개 STUN(`stun.l.google.com`, `stun.cloudflare.com`)을 쓰며 엄격한 NAT(회사망 등)에서는 연결이 안 될 수 있다 (TURN 서버는 쓰지 않는다).
- **라운드 시작 알림:** 증강 선택이 끝나고 그 라운드 첫 플레이어의 턴이 오기 직전에 보드 중앙에 `라운드 N`(64pt)이 크게 뜬다 (`EventAnnouncer.BIG_TAG`). 다른 알림과 같은 대기열이라 앞선 알림이 끝나야 나온다.
- **카드 UI 골자 (유희왕식 한 장 카드):** 모든 카드 화면(손패·드래그·사용 알림)은 같은 구조다: 맨 위 카드 이름 판 → 큼직한 일러스트 창 → 아래 세부 내용 상자(`[즉발 · 타일 설치]` 같은 종류 줄 + 효과 요약). **카드 배경색이 속성(카테고리)을 알려 준다**: 즉발 주황 / 함정 보라 / 소환 청록 (`CARD_BG_COLORS`). 카드는 140x196이고 크기에 비례해 모든 부분이 늘어난다 (`_build_card_body`).
- **일러스트 슬롯:** `assets/cards/<카드ID>.png`(예: `TRP_02.png`)를 넣으면 그 그림이 일러스트 창에 꽉 차게(비율 유지로 잘라서) 표시된다. 파일이 없으면 카테고리 색 원형 엠블럼 + 카드 이름 첫 글자를 쓴다.
- **손패 배치 (하스스톤 모바일 방식):** 손패에서는 카드가 화면 아래로 반쯤 가려져 이름과 일러스트 윗부분이 보이고, 부채꼴(장당 5도, 최대 ±16도)로 겹쳐 펼쳐진다. 호버하면 그 카드가 똑바로 서며 위로 올라와 세부 내용까지 전체가 보이고 1.08배로 커진다. 클릭 확대(효과·발동 타이밍·사용법)와 드래그 발동은 그대로다.
- **진행 방향 아이콘:** 보드 양옆에 은은하게 깜빡이는 쌍화살표(`>>`)가 진행 방향을 보여 준다. 정방향은 오른쪽이 위·왼쪽이 아래(반시계), 우노 리버스면 둘 다 뒤집히고 주황색이 된다. 상단 리본의 `진행 방향` 글자는 없앴다.
- **증강 선택 화면 (TFT 스타일):** 라운드 시작 드래프트는 알파 0.78 암막 위에 `준비` 소제목과 금빛 발광 `증강 선택` 제목을 띄우고, 세로형 카드 3장(260x390)을 나란히 놓는다. 카드는 위 45% 엠블럼(원형 후광 + 120px 원형 도장 + 큰 글자, 이모지 없이 도형·글자만 사용) / 중간 15% 제목(`[기물 진화] 체스: 나이트`, 흰색 21pt) / 아래 40% 능력 설명(밝은 회백색, 자동 줄바꿈)으로 나뉜다. 카테고리별 테마 테두리: 기물 진화 청록, 판정 도구 보라, 교칙 제정 금색, 생떼 카드 패키지 빨강. 호버하면 카드가 1.06배로 커지고 금빛 광채가 짙어진다(Tween). 카드 아래 `[ 리롤 (1회) ]` 버튼은 그 슬롯을 같은 드래프트에서 한 번만 다른 증강으로 바꾼다 (`reroll_augment` 액션, 슬롯별 1회, 현재 제시된 증강과 겹치지 않는 선택 가능한 증강을 `state.rng`로 뽑는다).
- **진화할 말 고르기:** 기물 증강을 고르면 숫자 버튼 대신 말 아이콘 카드 4장(150x200: `N번 말` 배지, 큰 말 도형, 출발 대기/출전 중 위치, `→ 폰 진화!`)이 뜬다. 이미 진화했거나 완주한 말은 어둡게 잠기고(`진화 불가`), 카드를 누르면 그 말이 진화한다. 호버하면 1.07배로 커진다.
- **이동할 말 선택 배너:** 굴림 뒤 `PHASE_SELECT_PAWN`(내가 조작하는 차례)이 되면 보드 아래 중앙에 `[어느 말을 N칸 이동시킬까요?]` 배너가 자동으로 뜬다. 말 카드 4장(135x165): 위쪽 `N번 말` 배지 + 상태(`출전 중 (12번)` / `출발 대기` / `★완주 완료`), 가운데 말 도형 + 세부 기물 이름(`비숍`·`차`·`흑돌`·`윷말`), 아래쪽 선택 결과 예고(`→ 16번 (옷장 워프!)`, `→ 10번 (점프!)`, `→ 4번 (빵집 카드 획득!)`, `→ 5번 (적 말 처치!)`, `→ 결승선 완주!`; 좋은 결과는 초록, 보통은 노랑). 예고는 실제 이동과 같은 `plan_path`(법전·기물 능력 반영)로 계산한다. 완주했거나 움직일 수 없는 말의 카드는 어둡게 비활성. 카드에 마우스를 올리면 카드가 떠오르고, 보드 위의 그 말이 크게 깜빡이며 이동 경로 타일이 굵은 노란 테두리(중간 5px, 도착 8px)로 표시된다(이때 배너 배경과 나머지 카드는 반투명). 카드(또는 보드 위 말)를 클릭하면 배너가 닫히고 이동한다. 우측 하단 독 슬롯과 같은 활성 상태를 쓴다.
- **기물 툴팁:** 슬롯·보드 위 말·프로필 아이콘에 0.35초 이상 커서를 대면 기물 이름 / 상시 능력 / 1회용 필살기만 크고 단순하게 뜬다 (세트 설명 없음).
- **하단 중앙 카드 독 (생떼 카드):** 손패 카드를 짧게 클릭하면 손패와 같은 카드 UI가 1.8배(252x353)로 확대되고 아래에 발동 타이밍·사용법·`지금 사용 가능`이 붙어 읽을 수 있고(남의 턴에도 가능, 다시 클릭하면 닫힘), 발동은 카드를 보드판 위로 드래그해서 놓는다. 드래그하는 동안 카드 UI가 그대로 따라오고 보드에 `[여기에 놓아 카드 발동!]` 드롭 존이 뜬다. 함정·소환 카드는 보드판에 던지면 "설치할 타일 고르기" UI(유효 타일 초록 테두리, 안내 배너, 취소 버튼)가 열리고 타일을 클릭하면 설치된다. 못 쓰는 타이밍이거나 보드 밖에 놓으면 손패로 돌아온다.
- **필살기 조작:** 룩은 맞바꿀 아군 선택, 차는 즉시 돌진, 비행기는 빵집·코너 타일 클릭, 흑돌은 슬링샷 조준 모드(마우스를 누른 채 뒤로 당겼다 놓으면 반대 방향으로 파워만큼 날아가고 직선의 적이 튕겨 나간다).
- **상단 UI와 메뉴:** 화면 상단에는 우측 상단의 `[메뉴]` 버튼(ESC로도 열고 닫음) **하나만** 둔다. 메뉴(오버레이)에는 `계속하기` / `게임 설정` / `전체 로그` / (혼자 하는 판에서만) `새 게임`·`[모드: 1P vs 3AI 봇 | 4P 수동 조작]`·`치트 / 디버그` / `게임 나가기`가 있다. `게임 설정`: 전체화면 켜기/끄기, 행동 사이 연출 멈춤(`GameSession.pacing_enabled`, `user://settings.cfg`에 저장), 제한 시간 사용(혼자 하는 판만; 온라인은 항상 켜짐 안내). `게임 나가기`는 확인 화면(`나가기`/`취소`)을 거쳐 시작 화면으로 돌아가며 온라인이면 내 자리는 컴퓨터가 이어받는다. 혼자 하는 판은 메뉴가 열려 있는 동안 봇이 멈추고 온라인은 멈추지 않는다. 터치 기기의 `전체화면` 버튼은 좌측 상단으로 옮겼다.

- **UI 이미지 스킨 (시험 적용, `UiSkin`):** 레퍼런스 기반의 글자 없는 패널·버튼 이미지(`assets/ui/trickcal/`, 생성 스크립트 `tools/generate_ui_skin.py`)를 `StyleBoxTexture`로 입혀 보드 화면의 패널·버튼에 쓴다. 이미지는 글자를 포함하지 않아 모든 문구는 코드가 그린다.
- **보드 시점과 아트 방향 (결정 기록):** 컨셉은 **"트릭컬 사도들이 테이블에 둘러앉아 보드게임을 한다"** 이다. 사도(Spine 2D 캐릭터)는 보드 위에 올라가지 않고 화면 가장자리의 아바타·컷신(감정 표현, 볼따구 당기기, 생떼)만 맡으며, 보드 위에는 보드게임 기물(윷말·체스 나이트 등)과 타일만 있다. 시점 후보는 A 탑뷰 / B 기울인 탑뷰 / C 정통 등각 / D 3D였고, 테이블에 앉아 판을 비스듬히 내려다보는 **B(기울인 탑뷰)** 를 우선 후보로 잡아 프로토타입을 만들었다(C는 AI 이미지 생성으로 타일 수십 장의 각도·조명을 일관되게 맞추기 어렵고 둘러앉은 느낌과 덜 맞아 후순위, D는 웹/모바일 부담과 컨트롤 기반 UI와의 충돌로 제외). 최종 확정은 비교 후 결정한다.
- **마름모 보드 (현재 구현, `MainBoard._surface_project`):** 규칙과 좌표(`BoardLayout`의 0~1 평면 좌표)는 그대로 두고, 화면으로 옮길 때 평면을 **45도 돌려 마름모**로 세운다(`DIAMOND_KX=520`, `DIAMOND_KY=330` (등각에 가까운 넓은 마름모); 0번 출발선이 아래 꼭짓점, 반시계로 오른쪽(6번) → 위(12번) → 왼쪽(18번) 꼭짓점). 대각선 타일이 없어 회전해도 규칙에 영향이 없다. 보드가 마름모가 되면서 화면 네 모서리에 빈 삼각 공간이 생겨 모서리 프로필이 보드 변에 붙어 앉는다. 양옆 쌍화살표(>>)는 없앴고 굴리기 버튼·파워 게이지·패드는 마름모 중앙 빈 공간(683, 335)으로 옮겼다. 두 시점(탑뷰/기울인 시점)은 같은 마름모 배치를 쓰고 **기울인 시점만** 펠트 테이블 배경·말 그림자·말 높이(`TILT_PAWN_LIFT`)·`y_sort`가 켜진다. 평면 받침 판은 쓰지 않고 항상 보드 면 메시를 그린다. 타일은 윤곽(투영된 둥근 마름모)으로 그려지고 클릭 판정도 윤곽을 쓴다. 기물 독(우하단 빨간 `말 1~4` 줄)은 내 프로필 카드가 말 칸과 필살기 버튼을 맡는 AI·온라인 모드에서는 숨기고 4인 수동 조작에서만 보인다. `메뉴 > 게임 설정 > 보드 시점`은 `user://settings.cfg`에 저장된다(기본 탑뷰).
- **좌석 배치 (구현됨):** 프로필 카드는 보드를 둘러싼 **네 모서리**에 앉는다. 나는 우측 하단(크게), 다음 순서는 우측 상단, 맞은편은 좌측 하단, 이전 순서는 좌측 상단이고(`MainBoard._compute_seats`), 인원이 적으면 1명=우측 상단, 2명=우측·좌측 상단이다. 처음에는 맞은편을 보드 위 가운데 한 줄 프로필로 두었으나 하나만 위에 떠 어색하고 보드 테두리와 겹쳐 네 모서리로 옮겼다. 보드 판은 위쪽 여백을 14px 늘렸다.
- **아바타 칸 (`AvatarSlot`):** 사도(Spine 2D)의 감정 표현이 들어갈 교체 가능한 슬롯. 에셋이 없으면 좌석 글자(P1~)와 감정 이름(웃음/분노/놀람/낙담/환호) 자리표시자를 보여 주고, `res://content_trickcal/avatars/<캐릭터>/frames.tres`(SpriteFrames, 애니메이션 이름 = `idle/happy/angry/surprised/sad/cheer`) 또는 `portrait.png`가 있으면 그것을 쓴다. 감정 반응은 에셋 유무와 상관없이 튕김·떨림·확대·테두리 번쩍임으로 보이고 시간이 지나면 기본 표정으로 돌아온다. 반응 시점: 말이 잡히면 피해자 angry/잡은 쪽 happy, 완주 cheer, 설치물 발동 surprised, 카드 사용 happy, 게임 종료 승자 cheer/나머지 sad. 락스텝이라 모든 화면에서 같은 반응이 보인다. 캐릭터 선택은 `[아바타 설정]`에서 한다(위). Spine 런타임 연동은 다음 단계, 에셋 규격은 `content_trickcal/avatars/README.md`.

### **4.6. 자동 발동 알림과 AI 대전 모드**

- **중앙 이벤트 알림 (`EventAnnouncer`):** 교칙 제정(법전 전체를 띄우고 새 줄 강조), 카드 사용(`[P2 발동!]`과 카드 앞면), 함정·설치물 발동, 교칙 작동, 증강 선택, 중립 기물 사냥·소멸, 체스 퀸 승진, 필살기, 친치로 삐끗이 보드 중앙에 1~2.6초 대기열 카드로 뜬다. 떠 있는 동안 사람의 입력과 봇의 행동이 잠기고 클릭하면 넘어간다.
- **AI 대전 모드:** 시작 메뉴 `[훈련]`에서 컴퓨터를 1~3명으로 고르면(기본 3명, `1P vs 3AI 봇`) P1만 직접 조작하고 컴퓨터는 `BotController`가 `TurnManager.act()`로만 행동한다 (사람과 같은 권한 검증). 판단은 `BotBrain`: 증강은 필살기 기물 > 윷말 > 다른 기물 > 도구 교체 > 교칙 순, 말 선택은 완주·잡기·코너/빵집 정차 점수, 카드·함정 사용, 개입 카드, 러시안 룰렛 멈춤, 그리고 1회용 필살기(적을 많이 맞히는 알까기 각, 앞선 적을 잡는 차 저격, 이득이 큰 워프, 위험할 때의 캐슬링)까지 판단한다. 봇의 함정은 `?함정`으로만 보이고(타일 은신) 봇의 손패는 보이지 않는다. 단계마다 0.3~0.8초의 호흡을 둔다.

### **6.2. 단계별 상세 이력과 결정 사항**

**0. 기반 (10-14)**
- 사용자 확정 엣지 케이스 명세(`EDGE_CASE_SPEC.md`)를 구현하는 `core_engine` 작성. 렌더링과 규칙을 분리해 코어는 UI 노드를 참조하지 않고 시그널로만 소통한다.
- 규칙 엔진은 `LawResource`/`RuleContext`/`RuleBookManager`(FIFO 4슬롯)로 재작성, 보드는 `TileNode` 링크 + `TileAttachment` 리소스 + `Node2D` 엔티티, 턴은 `CommandStack`(되돌리기/개입)과 8단계 `TurnManager` FSM.
- 핫시트 플레이 프로토타입(`main_board.tscn`)으로 코어를 시각 검증.

**1~2. 코어 루프와 기물 (10-15)**
- 증강 드래프트·기물 세트·타일 지정 카드·승리 조건 완성, 나머지 기물 능력·ACT_02/03·호텔 밸런스 구현.
- 배포 자동화: `update.bat`(원클릭 갱신)와 `deploy-web.yml`(테스트 통과 시 Godot 웹 빌드를 `gh-pages`에 올림).
- 보드 배치를 우하단 출발·반시계 방향으로, 출발 전 대기 말은 보드에 그리지 않고 첫 걸음에 출발선에서 나타나게 변경.
- **결정:** 세트 효과·세트 특수 승리 삭제 → 승리는 "내 말 4개 완주" 하나. 대신 기물 단독 상시 능력과 1회용 필살기 4종(흑돌 알까기·차 저격·룩 캐슬링·비행기 워프)을 둠 (이후 쇼기 보병 모치고마 낙하가 더해져 현재 5종). 증강의 기물 지급은 무작위 진화에서 **세부 기물 지정 지급**(이미 가진 기물은 받을 수 없음)으로 바뀜. 장기 4세트 잡기 추가 턴·업기/잡기 추가 턴은 윷놀이 기물 고유 능력으로 이관. 할리갈리 적립기는 삭제하고 지하노역장 친치로(사기 주사위)로 교체.
- 호기별 세부 기물(체스·장기·모노폴리·바둑)과 고유 능력, 중립 기물(도적·고스트)은 한 번 잡으면 소멸.

**3. AI 대전과 HUD (10-15)**
- `BotBrain`(말 선택 점수 = 완주 > 잡기 > 코너/정지점 > 전진, 증강·함정 타일·개입 카드·룰렛 판단)과 `BotController`(사람과 같은 `act()` 권한 검증으로만 행동, 단계별 대기 시간).
- 상용 보드게임식 HUD: 모서리 프로필(2x2 기물 슬롯, 스포트라이트 명암), 우하단 기물 독, 호버 능력 툴팁, 판정 도구 전광판, 카드 확대/드래그 발동, 중앙 이벤트 알림, 타일 은신 함정(AI 모드에서 상대 함정은 뒷면).
- 시작 메뉴: 닉네임 설정(1~10자, `user://profile.cfg`) → `컴퓨터 대전`/`멀티플레이`.
- **결정:** 글씨 대신 아이콘과 명암으로 상태를 전달(미니멀 HUD), 안내 문구 제거, 상단 라운드/턴 리본 제거(프로필 강조와 라운드 알림으로 대체), 타일 번호 글자 삭제.

**4. 모바일과 UI 대개편 (10-15)**
- 모바일: 세로 화면 가로 안내, 전체화면/가로 고정 버튼, 웹 셸 확대·스크롤 차단, 보드 520px 확대, 모두의 마블식 둥근 굴리기 버튼, `stretch expand`·좌/중/우 묶음 배치·안전 여백 12px.
- 굴림 위젯 분리: **차징형 주사위만 중앙 무대 아래쪽에 작게**, 룰렛·리볼버·홀덤/슬롯은 보드 한가운데 크게. 룰렛은 원판을 잡아 돌리고 러시안 룰렛은 리볼버 방아쇠를 당긴다. 굴림이 끝나면 위젯을 숨겨 중앙을 가리지 않는다.
- TFT식 증강 선택(엠블럼·호버 광채·슬롯별 리롤)과 이동할 말 선택 배너(결과 예고·보드 깜빡임), 기물 진화 대상은 숫자 대신 말 아이콘 카드로 선택.
- 라운드 시작 대형 알림, 보드 양옆의 은은한 진행 방향 아이콘, 모바일 하스스톤식 손패(일러스트+이름만, 부채꼴로 반쯤 가림, 호버 시 전체 노출).
- 카드 UI는 유희왕식 한 장 카드로 통일: 이름 판 / 큰 일러스트 / 세부 내용, **배경색 = 속성**, 일러스트 파일 슬롯.
- 판정 도구 카드에 **전체 규칙표(족보·눈금·확률)** 표시: 새로운 방식의 도구는 유저가 모르므로 족보를 전부 알려 준다.
- 진행 방향 화살표가 증강 선택 위에 그려지던 문제는 `z_index`로 수정.

**5. 규칙 흐름 정리 (10-15)**
- **카드는 굴리기 전 턴당 1장**이 기본. 유일한 예외인 바이츠 더 더스트(피해를 되돌림)만 정산 창에서 중앙 팝업(6초)으로 발동 여부를 묻고 시간이 지나면 넘어간다.
- 증강을 1·4·7라운드에서 **1라운드부터 3라운드마다 계속**(1, 4, 7, 10, ...) 열도록 변경: 이미 쓴 기물을 처리할 수 있고 주기적 변화가 핵심이기 때문.
- 증강 선택은 클릭 즉시 적용하지 않고 [선택 연출 → 말 선택] 단계를 둠. 우측 독은 상태 표시 전용.
- 행동 사이 호흡: 이동 뒤 멈춤, 턴 시작 `[N 차례]` 알림, 봇 대기 시간 상향.

**6. 멀티플레이 로비 (10-16)**
1. *WebRTC 직접 연결 로비:* 서버 없이 초대/응답 코드를 주고받는 수동 시그널링(`TRG1-...`, 당시 방식이며 이후 5자리 방 코드 자동 시그널링으로 대체되고 수동 연결 UI는 제거됨), 좌석 모델(`열림/초대 중/사람/컴퓨터`), 실제 Chromium 2개 e2e 검증.
2. *5자리 방 코드 자동 시그널링:* 긴 SDP 코드를 숨기고 공개 Pub/Sub 릴레이(ntfy.sh)로 자동 교환. 방장은 좌석별 초대를 `trg_sig_{코드}_o{좌석}`에 올리고 참가자가 응답을 `_a{좌석}`에 올림. 자리 선점은 "표식(nonce)이 같은 첫 응답"으로 결정, 봇으로 채운 자리는 닫힘 표식. 수동 코드는 `고급: 수동 코드 연결` 접이식 메뉴로 보존.
3. *빠른 랜덤 매칭:* 공용 대기열 `trg_matchmaking_queue_v1`에 `OPEN_ROOM` 비콘(3초 주기, 12초 신선도). 열린 방이 있으면 자동 입장, 없으면 방장이 되어 15초 대기 후 AI로 빈자리를 채워 시작. 동시에 방을 연 사람끼리는 코드가 큰 쪽이 작은 쪽으로 합류. 카드형 메뉴 3개(`빠른 랜덤 매칭`/`친선전 방 만들기`/`방 코드로 입장`).
- **결정/수정:** 공개 ntfy.sh의 요청 제한(처음 60회, 이후 5초에 1회)을 피하려고 여러 토픽을 쉼표로 묶은 한 번의 요청(`fetch_many`)으로 읽고 방이 오래 열려 있으면 폴링 간격을 늘림. 로비를 떠날 때 `multiplayer_peer`를 `null`이 아닌 `OfflineMultiplayerPeer`로 되돌림(그렇지 않으면 이후 게임 화면의 `get_unique_id()` 오류). 이모지는 폰트에 없어 쓰지 않음(`📋 🚀 ⚡ 🔑` 대신 글자).

**7. 클래식 보드게임 콘텐츠 6종 (10-16)**
- 쇼기 기물(1호기 보병·2호기 비차·3호기 각행·4호기 계마, 나리 승급, 모치고마 낙하), 판정 도구 3종(화투 고/스톱·리치 마작·점성술사의 타로 덱), 함정 `TRP_05` 도미노 연쇄 붕괴, 타로 즉발 카드 2장.
- **결정:** 사용자가 적은 `ACT_06`은 이미 '이의 있음!'이라 새 카드를 `ACT_07`(XVI 무너지는 탑)·`ACT_08`(X 운명의 수레바퀴)로 부여. 모치고마 낙하는 "턴 시작 때 언제든 사용 가능"으로 해석. 원칙 유지: 세트 효과 없음, 판정 도구는 이동 칸수만 계산.

**8. 온라인 대전 (10-16)**
- 요구: "무조건 AI를 끼고 싶지 않은 사람도 있으니 2인에서도 작동". 로비만 있던 상태에서 게임 화면 동기화를 구현했다.
- **락스텝 채택 이유:** `MainBoard`(4000+줄)가 로컬 `TurnManager`의 시그널·내부 상태에 깊이 묶여 있어 상태 방송 방식은 화면 전체를 다시 짜야 한다. 락스텝은 엔진이 `GameState.rng`(시드 고정)로만 결정되는 점을 이용해 **같은 코드가 모든 화면에서 같은 판을 재현**한다.
- 구현: `TurnManager`에 `lockstep`·`action_interceptor`·`external_timeouts`·`timer_scale`·`apply_replicated`·`state_hash`, `NetGame`(방장 순서 결정·사칭 차단·이동 연출 중 대기·준비 대기·자리 인계·핑), `BotController`(온라인용 `draft_waits_for_humans`/`wait_for_human_windows`), `GameSession` 온라인 설정, `LobbyService.begin_online_game`, `MainBoard` 온라인 모드(내 자리 우하단·없는 자리 숨김·치트 숨김).
- 인원 규칙: 혼자면 AI 3명과 대결, 사람이 둘 이상이면 지금 명단 그대로(비워 둔 자리는 빠지고 `AI 봇으로 채우기`를 누른 자리만 AI) 2~4인.
- 주의 사항: 모든 참가자가 전체 상태를 계산하므로 정보 은닉이 없다(친선전용). 방장이 멈추면 전원이 멈추고 방장 이양은 없다. 웹 브라우저가 보이지 않는 탭을 멈추는 한계는 핑 기반 안내로만 완화한다.
- 혼자 테스트하는 법: 브라우저 창 두 개를 나란히(탭 전환은 안 됨).

**9. 배포 (10-15 ~ 10-16)**
- `deploy-web.yml`: 테스트(단위·ui_smoke 수동/AI·ui_fx·ui_lobby·ui_net 2종) 통과 → Godot 웹 내보내기 → `gh-pages` 강제 푸시 → (선택) Vercel CLI 배포(시크릿이 있을 때).
- `vercel.json`(정적 호스팅, 캐시 재검증, wasm 타입)을 빌드 산출물에 포함. 운영 주소는 `https://trickcal-board.vercel.app/` (Vercel Production Branch = `gh-pages`). 구 GitHub Pages 주소도 `gh-pages`가 켜져 있는 동안 열린다.
- 폰 캐시 문제 회피용으로 주소 끝에 `?v=N`을 붙이는 방법을 배포 안내마다 알림(마지막 안내 `?v=27`).

**10. UI 정리와 시점 연구 (10-16)**
- 상단 버튼을 `[메뉴]` 하나로 줄이고 계속하기/게임 설정/전체 로그/새 게임/모드/치트/게임 나가기(확인)를 메뉴로 이동. 치트/디버그 서랍은 개발용이라 나중에 제거하기로 결정.
- 시점 논의: 보드 위에는 Spine 캐릭터가 올라가지 않고(아바타·컷신 전용) 기물만 올라가므로 시점과 Spine은 독립적이라는 점을 확인. 컨셉이 "테이블에 둘러앉아 보드게임"이라 기울인 탑뷰를 우선 후보로 프로토타입(`MainBoard.ViewMode`, `_project`). 원본 에셋 사용은 권리 문제 확인이 필요하고 공개 저장소·배포에 올리지 않도록 `content_trickcal/` 분리 유지.
- 테이블 좌석 배치(나=아래, 맞은편=위 가운데 한 줄 프로필, 좌우)와 교체 가능한 아바타 칸(`AvatarSlot`: 에셋 없으면 자리표시자, SpriteFrames/portrait 연동, 감정 반응 6종)을 구현. 2인 대전에서는 상대가 맞은편에 앉는다.
- 정정: 출발/완주 칸은 모든 좌석이 공유하므로 "인원이 적으면 출발 코너가 좌석에 따라 정해진다"는 기존 서술은 틀렸다(바로잡음).

**11. 로비 UI 재스킨 (10-16)**
- 사용자가 갓필드식 로비 스크린샷(타이틀+이름 입력, 큼직한 모드 카드, 비밀 방 패스워드 팝업, 방 슬롯 목록, 위/아래 청록 띠)을 레퍼런스로 제시해 시작 메뉴와 로비를 밝은 민트/청록 테마로 전면 재스킨. 이름은 이 게임의 세계관에 맞게 `교주의 이름`/`훈련`/`비밀 결투`/`랜덤 결투`로 바꿈. `훈련`에 AI 인원(1~3) 선택을 추가(메인 보드가 참가 인원에 맞춰 좌석·봇 구성). 로직·노드 이름은 유지하고 스타일과 흐름만 바꿨다.
- 후속 결정: `진지 승부`는 `랜덤 결투`로 이름 변경, 수동 코드 연결(`고급` 메뉴)은 제거(자동 연결만), 아바타를 고르는 설정 화면을 추가했다.
- 아직 안 한 것: 레퍼런스의 인원 수 표시(`예언자 N명`)는 서버가 없어 보여 줄 수 없고(카드 띠는 설명 문구로 대체), 채팅/계시록/볼륨 막대는 넣지 않았다.

### **6.6. v3.0 개정 기록 (10-16)**

- **수동 코드 연결 제거 / 모드 이름:** 방 코드 5자리 자동 연결만 지원한다. 메뉴는 `훈련 / 비밀 결투 / 랜덤 결투`(옛 "진지 승부"는 "랜덤 결투"로 개명). `[아바타 설정]` 화면 추가, 아바타는 온라인 명단·시작 설정으로 모든 화면에 같게 전달된다.
- **가로 고정:** `handheld/orientation`=가로 + 웹 셸의 세로 덮개 + 첫 터치 때 `screen.orientation.lock` 시도.
- **좌석 네 모서리 / 내 프로필:** 맞은편 프로필을 보드 위에서 좌측 하단으로 옮기고, 내 프로필을 키워 기물 칸 아래의 `필살기` 버튼으로 필살기를 쓴다 (`active_skill_buttons()`). 보드 판을 14px 내려 위쪽 겹침을 없앴다.
- **진화할 말 고르기:** 말 고르기 창이 뜨는 동안 증강 카드 화면을 숨겨 겹쳐 보이던 문제를 고쳤다.
- **카드 상세:** 클릭 확대가 손패와 같은 카드 UI(1.8배)로 바뀌었다.
- **문서:** 이 문서를 구현 기준 v3.0으로 전면 개정 (2.4 신설, 3.1 좌표계, 4.1 필살기 요약, 4.2/4.4 표, 4.5 UI 정정, 5 디렉토리).
- **규칙 단순화 2차 (10-17):** `뱅!`(프로필 선택 -> 선두 말 2칸 후퇴)에 이어 복잡한 규칙을 걷어냈다. ① **우노 +4**: 보류 페널티·폭탄 떠넘기기(`pass_bomb`)를 없애고 다음 유저 선두 말이 즉시 4칸 후퇴. ② **지뢰찾기**: 양옆 숫자 타일(`MINE_NUM`)을 없애고 은신 지뢰 1개만. ③ **윷 업기**: 선택창 없이 자동 업기 (코어의 `stack_choice` 경로는 남아 있으나 보드는 끈다). ④ **화투**: 고/스톱·피박을 없애고 패 2장 한 번에 판정. 관련 테스트는 새 규칙으로 바꿨다.
